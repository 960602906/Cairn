# ADR-0033 运行检查器与上下文快照

- 状态：已接受（M4-04）
- 日期：2026-11-08
- 详细设计：[Agent 管理界面](../design/agent-management-ui.md) §8.1、§8.2；[Agent 运行时](../design/agent-runtime.md) §12、§13、§15
- 相关决策：ADR-0005、ADR-0009、ADR-0010、ADR-0020、ADR-0030

## 背景

多 Agent 协作后，一次会话会同时存在父运行与多个子运行。用户需要回答三类问题：谁在做什么、模型实际看到了什么、运行为什么停下来。事件日志已经记录了完整的运行过程，但它是面向追加与恢复的线性结构，不适合直接展示；上下文只存在于宿主进程内存中，运行结束后无法回看。候选方案：

1. 渲染进程直接读取事件日志并自行聚合；
2. 主进程维护一份独立的运行状态，并再写一份检查器数据；
3. 主进程按需从事件日志投影运行树，并在模型调用前持久化最小化快照。

方案 1 会把事件结构暴露给渲染进程，且每个视图都要重复实现聚合；方案 2 引入第二份状态，容易与事件日志不一致。

## 决定

- **运行树是事件投影，不是第二份状态。** `projectRunTree()` 在读取时从事件日志重建运行、轮次、步骤、工具调用、审批、用量与状态；不写入新的事件，也不参与调度决策。父子关系、当前状态、失败原因都以事件为准。
- **快照在模型调用前生成。** 宿主在每次真正发起模型请求前生成 `RunSnapshot`，包含系统提示词各部分、加载的 Skills、工具定义、历史预览与压缩摘要、估算 token，经主进程 `host.snapshot` 写入存储。失败只记录日志，不影响模型调用本身。
- **只保存必要内容。** 快照只包含渲染检查器所需的结构与预览：单个系统提示词部分最多 4k 字符，工具与 Skill 描述最多 500 字符，历史最多最近 20 条且每条 400 字符预览，压缩摘要最多 2k 字符；不保存完整消息正文、工具输出正文或凭据。
- **明确大小上限。** 单份快照上限 32k 字符；超限时先丢弃最旧的历史预览，再逐步减半最长的系统提示词部分、工具描述与 Skill 描述。预计 token 使用现有 `estimateTokens()` 估算，不承诺与供应商计费完全一致。
- **按运行保留最近 20 份。** 新迁移 `0011-run-snapshots` 建立 `run_snapshots` 表与 `run_snapshots_by_run` 索引；每次写入后按创建顺序裁剪同一运行的旧快照，保证存储增长有界。
- **路径与凭据脱敏。** 主进程写入前把工作区路径转换为项目相对路径或 `~`；凭据、令牌与 API Key 不进入快照。允许保留模型名称、Agent 标识与工具名称。
- **访问边界。** 运行树与快照只在主进程读写；渲染进程通过只读 `run.inspect` 获取 `RunInspectResult`，不能直接访问存储，也不能修改运行状态。`host.snapshot` 是宿主到主进程的内部 RPC，不暴露给渲染进程。
- **不显示金额。** 用量按运行与 Agent 分组，包含模型调用次数、工具调用次数、输入/输出/缓存/推理 token 与时长；不换算货币，避免与供应商计费口径混淆。
- **不引入新依赖。** 投影、截断与脱敏使用现有工具与存储层。

## 备选方案

- **渲染进程直接聚合事件**：需要把事件结构暴露给渲染进程，并重复实现多套聚合逻辑，不采用。
- **主进程维护独立运行状态**：查询更快，但会与事件日志产生双写与漂移风险，不采用。
- **保存完整上下文**：调试信息最全，但体积、隐私与凭据风险不可接受，不采用。
- **按需重建上下文**：需要重放模型调用，结果不确定且代价高，不采用。

## 后果

- 运行树的正确性依赖事件日志的完整性；新增事件字段时必须保持可选并兼容旧日志。
- 快照是有损预览，历史与工具输出只能看到摘要；需要完整内容时仍应回到事件日志或诊断包。
- token 是估算值，用于比较与预警，不作为计费依据。
- 每个运行最多保留 20 份快照，长时间运行会丢失更早的调用记录；这是存储有界性的有意取舍。
- 检查器只读，不提供重试、取消或编辑能力；这些操作仍由现有会话与审批入口完成。
