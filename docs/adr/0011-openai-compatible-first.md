# ADR-0011 模型接入以 OpenAI 兼容接口优先

- 状态：部分被 [ADR-0021](0021-three-api-formats.md) 替代（首批接口格式改为三种）
- 日期：2026-11-02

## 背景

首批接入 DeepSeek 和 Ollama，两者都提供 OpenAI 兼容接口。后续还要支持 Anthropic、OpenAI、Google 等。不同模型在上下文窗口、工具调用、推理内容等能力上差异很大，尤其是本地模型。

## 决定

- 提供方配置包含 `kind` 字段，第一版只实现 `openai-compatible`，DeepSeek 和 Ollama 都使用它。
- 每个模型有 `ModelProfile`，记录上下文窗口、最大输出、是否支持工具调用、并行工具调用、推理内容等能力。
- 提供"测试连接"进行能力探测，结果写回 `ModelProfile`。
- 上下文预算、工具输出截断等策略根据 `ModelProfile` 计算，不写死。
- 实际的模型调用由 pi-ai 完成，经由 `runtime-pi` 适配器转换配置。

## 备选方案

- **为每个提供方单独写配置界面和逻辑**：首批两个提供方会重复工作。
- **只配置 baseUrl 和模型名，不记录能力**：无法针对小上下文或不支持工具的模型做出合理处理。

## 待预研

- DeepSeek 推理类模型的思考内容字段与工具调用在 pi-ai 下的兼容性。
- 常见 Ollama 模型的工具调用成功率，据此给出推荐模型列表。

## 后果

- 新增提供方类型时只需扩展 `kind` 和适配器转换逻辑。
- 能力探测增加了一次额外请求，但能提前发现不兼容问题。
