# ADR-0005 以追加式事件日志作为会话的事实来源

- 状态：已接受
- 日期：2026-11-02

## 背景

一个会话中包含用户消息、模型回复、工具调用、审批、文件改动、检查点等多种活动。需要支持：实时显示、界面重载后恢复、应用重启后继续对话、回退到某一步、调试和诊断。如果把"当前消息列表"直接作为存储格式，回退、分支和审计都很难实现。

## 决定

- 所有会话活动都表示为带信封的事件（`v`、`sessionId`、`seq`、`ts`、`turnId`、`type`、`payload`），追加写入事件日志。
- `seq` 由主进程分配，保证会话内单调递增。
- 增量事件（`*.delta`）只用于实时推送，不落库；对应的完成事件保存完整内容。
- 界面状态由事件归约得出，归约函数放在 `packages/core`，界面与测试共用。
- 界面订阅时携带 `afterSeq`，由主进程补发缺失事件。
- 事件 schema 只做向后兼容的追加；不兼容变化需要提升版本并提供迁移。

## 备选方案

- **只保存当前消息列表**：简单，但无法追溯过程，回退和分支困难。
- **保存 pi 的原生会话格式**：与 ADR-0004 冲突，且受 pi 版本影响。

## 后果

- 需要设计事件类型并维护归约逻辑。
- 天然支持断线恢复、回放、审计和诊断包导出。
- 后续实现会话分支（从某一步分叉）只需在事件层增加分支引用。
