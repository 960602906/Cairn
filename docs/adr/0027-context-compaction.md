# ADR-0027: 上下文压缩与历史重建策略

## 背景

在长会话场景下，多轮对话累积的输入与工具调用很容易逼近乃至超出大模型的最大上下文窗口（Context Window）。若直接丢弃早期消息，会导致模型丢失关键业务目标、技术方案选择与修改上下文；若全部保留，则会导致调用报错或成本急剧上升。

## 决策

1. **压缩触发阈值**：在每次调用模型前（`RuntimeHooks.beforeModelCall`）动态计算上下文占用。当历史预估 token 达到有效可用空间（`contextWindow - reservedOutputTokens - systemPromptAndTools`）的 80% 时，自动触发上下文压缩。
2. **保留策略**：
   - 保留最近 2 轮完整对话（用户消息、思考过程、工具调用与结果），确保模型具备直接工作记忆与连贯上下文。
   - 切割点严格定位在用户消息边界，禁止将工具调用与工具返回拆分在压缩线两侧。
3. **结构化摘要提取**：
   - 调用轻量快速的辅助模型，将更早历史压缩为标准 Markdown 结构化摘要：用户目标、关键技术决策、已修改的文件清单、当前待办与未完成事项。
   - 结构化摘要作为前置引导消息注入后续模型历史。
4. **事件溯源与历史重建**：
   - 压缩产生持久化事件 `context.compacted`，记录轮次范围、压缩前后的预估 token 与可选的 seq 范围。
   - 会话历史恢复时由 `rebuildHistory` 直接应用最后一次压缩结果，避免重新向模型发送已压缩消息。
   - 界面上在被压缩位置展示折叠线与展开摘要，原始事件流完整保留在数据库中，不破坏审计。
5. **降级机制**：若辅助模型总结失败，降级为截断并丢弃最早一轮的工具返回大输出，在对话流中展示“部分工具输出已省略”提示，确保会话不中断。

## 状态

已采纳并实施（M3-03）。
