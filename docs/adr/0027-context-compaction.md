# ADR-0027 上下文压缩：摘要替换模型历史，原始事件保留

- 状态：已接受
- 日期：2026-11-07

## 背景

长对话会撑满模型的上下文窗口。Runtime §8.3 要求在调用模型之前估算占用，超过可用空间的 80% 时压缩：保留最近两轮，更早的内容交给辅助模型总结。原始事件不能删，界面仍显示完整对话。恢复会话时按最后一次压缩重建发给模型的历史。

`context.compacted` 与 `RuntimeHooks.beforeModelCall` 在更早的阶段已经定义，但运行时还没有接上。

## 决定

- 压缩是一次独立的辅助模型调用，不进入当前轮次的工具循环，也不写成用户消息。用量记为 `usage.reported` 且 `auxiliary: true`，计入统计，不靠这次用量去改上下文圆环。
- 触发线是“上下文窗口 − 预留输出 − 系统提示词与工具定义”的 80%。预留输出取 `min(最大输出, 窗口的一半)`。估算沿用现有的字符估算，没有分词器。
- 保留最近 2 轮的完整内容。只在用户消息处切开，工具调用和它的结果留在同一侧。更早的部分（含上一次摘要）交给辅助模型。摘要要保住用户目标、已做的决定、改过的文件和未完成的事，用用户的语言，不编造。
- 摘要作为 `summary` 消息放在模型历史开头。发给模型时前面加固定的英文前缀，让模型知道这是摘要而不是新的用户输入。
- pi 的 `transformContext` 只影响这一次请求：同一轮后面的步骤继续用传入的数组，下一轮从 `state.messages` 取快照，会话自己还有一份带 `turnId` 的历史。三处都要写成压缩后的内容，并且要改传入的那个数组本身。
- 原始事件保留。`context.compacted` 补上被替换的轮次、压缩前后的估算占用，以及可选的 seq 范围。宿主不知道 seq，范围由主进程按轮次 id 在落库前补上。`rebuildHistory` 用最后一次摘要换掉它覆盖的轮次；再压缩时新摘要换掉旧的。
- 摘要失败、或没有可总结的更早轮次但历史已经超限：从最早的工具结果开始，把输出换成“输出已省略”的说明，调用记录保留。界面只提示一次。
- 输入 `/compact` 立即压缩，不发给模型。轮次还在跑时排到这一轮结束。不足两轮更早内容、又没有可丢的工具输出时什么都不做。
- 压缩事件上的 `tokensAfter` 含系统提示词和工具定义的开销，上下文圆环立刻下降。下一次主模型的真实用量会再写一次圆环。
- 会话要点（M3-04）不在这次里。有了要点之后，压缩时把它放进摘要之前。

## 备选方案

- **直接删掉更早的消息**：实现简单，但用户在界面上看不到自己说过的话，也没法从日志里核对模型当时看到了什么。
- **只在 pi 的返回值里换掉这一次的上下文**：同一轮的后续步骤和下一次 `prompt` 仍带着完整历史，压缩等于没发生。
- **在宿主里分配 seq**：seq 由主进程在落库时分配。宿主去猜会和真正写入的序号对不上。

## 后果

- 新增 `host.summarize` 与 `host.compact`、`session.compact`。摘要在主进程里调用，凭据不进宿主的日志。
- 用户消息可以带可选的 `turnId`，旧历史没有这个字段仍然能读。
- 手动压缩在没有运行中的宿主时，直接根据事件日志压缩并写下 `context.compacted`，下次启动宿主时 `rebuildHistory` 会用到它。
