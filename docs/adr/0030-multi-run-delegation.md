# ADR-0030 同一宿主内的多运行、父子运行与委派边界

- 状态：已接受（M4-00 起草；M4-01 落地多运行与父子运行部分，M4-02 落地委派协议与 `delegate` 工具；M4-15 联合验收）
- 日期：2026-11-08
- 详细设计：[多 Agent 协作](../design/multi-agent.md)、[Agent Runtime](../design/agent-runtime.md) §16
- 相关决策：ADR-0003、ADR-0005、ADR-0016、ADR-0018、ADR-0020

## 背景

ADR-0020 确定了以父运行为中心的委派模型，但当前 `RunSupervisor` 仍是单运行版本：同一时间只允许一个 `RunEngine`，`run.delegated` / `run.child.completed` 只有占位字段。M4 要支持并行只读子运行、父子预算与取消传播，必须先决定运行在宿主中的组织方式。

候选方案：

1. 每个子运行创建独立宿主（独立 `utilityProcess`）；
2. 同一宿主内管理 N 个运行，每个运行独立的 `RunEngine` 与运行时会话；
3. 保持单运行，在 `RunEngine` 内嵌套子循环。

方案 1 隔离最彻底，但每个宿主都要重复加载运行时、模型与工具，事件与审批要跨进程聚合，M4 的成本与故障面都过大；方案 3 把父子生命周期塞进一个引擎，无法独立取消、限额与恢复。

## 决定

- **同一宿主内管理 N 个运行。** `RunSupervisor` 的 `createRun` 接受可选的 `parentRunId`，运行 id 在同一会话内全局唯一；每个运行有自己的 `RunEngine`、运行时会话、模型、系统提示词、工具、检查点与中止信号。
- **不共享对话历史。** 子运行只接收任务书与系统自动附加的会话要点；父运行只接收结构化结果，不接收子运行历史。
- **父运行等待。** 父运行在等待子运行时进入 `awaiting_children`；全部子运行结束后回到 `tooling`，结果作为工具结果回填，再进入 `thinking`。
- **取消树。** 父运行中止时级联中止所有子运行；单个子运行中止时父运行继续，子结果标记为 `aborted`；宿主关闭时全部中止。
- **预算继承。** 子运行限额取“子 Agent 限额、任务书预算、父运行剩余预算 × `childBudgetShare`”三者的最小值；子运行消耗计入父运行本轮消耗，父运行达到限额时子运行一起停止。
- **权限不放大。** 子运行的有效权限是子 Agent、父运行与委派策略的交集；计划模式下子运行只读；“本会话始终允许”仍受子 Agent 自身权限约束。
- **事件归属。** `run.delegated` 必须在子运行 `run.created` 之前写入；`run.child.completed` 必须在子运行 `turn.completed` 之后写入；所有事件写同一会话事件流，`seq` 由主进程分配。
- **深度与并发。** 默认委派深度 1，可配到 2，全局硬上限 3；`maxParallel` 与 `maxChildrenPerTurn` 由委派策略限制，超过上限排队而不是失败；禁止循环委派与重复任务。
- **不提前物化运行树。** M4 先以事件投影构建运行树；只有 M4-04 证明投影性能不足时才新增物化表与迁移。

## 备选方案

- **每个子运行一个独立宿主**：取消与预算需要跨进程协调，事件顺序更难保证；S1 证明同一宿主可以隔离会话，因此不采用。
- **共享父运行历史**：实现简单，但抵消上下文收益并引入无关干扰，违反 ADR-0020。
- **在 `RunEngine` 内嵌套子循环**：无法独立恢复、取消与限额，不采用。

## 后果

- `RunSupervisorOptions` 需要从“一个 supervisor 一个模型”改为按运行创建上下文（`createRunContext`）。
- 同一宿主的多运行会共享进程级资源；M4-13 必须压测内存、CPU、工具并发与事件吞吐，必要时限制每会话运行数。
- 子运行的事件与审批必须带 `runId` / `parentRunId`；运行树、活动中心与检查器都只读事件投影，不维护第二份状态。
- 崩溃恢复时父运行与子运行都按中断处理，不重复执行已完成的工具。
