# ADR-0047 目标模式：可验证完成条件、独立判定与自动续轮

- 状态：已接受（实施）
- 日期：2026-11-25
- 相关决策：ADR-0005（事件日志是事实来源）、ADR-0018（交互运行与无人值守运行）、
  ADR-0027（上下文压缩）、ADR-0028（计划模式）、ADR-0038（待办列表独立于计划模式）、
  ADR-0044（用户提问）、ADR-0046（消息编辑与回退）
- 相关文档：[Agent Runtime](../design/agent-runtime.md) 第 23、25 节；
  [目标模式落地方案](../plan/goal-mode.md)

## 背景

Cairn 的一轮在模型结束回复时结束。用户要求“让测试通过”“把迁移做完”这类需要多轮推进的目标时，
只能一轮一轮盯着：模型停下后手动发“继续”，或者在外部用脚本反复调用。计划模式解决的是动手前的
对齐，待办列表解决的是进度展示，无人值守运行解决的是没有用户在场时的审批策略；三者都不回答
“这件事什么时候算完成，由谁来判断”。

其他编程 Agent 已经把 `/goal` 收敛成一个独立原语：用户给出一个可验证的完成条件，每轮结束后由
一个独立的判定者检查条件，未达成就自动开始下一轮，直到达成、判定不可能、预算耗尽或用户停止。

约束：

- 事件日志是唯一事实来源（ADR-0005）。目标、每次判定与结束原因必须落事件，宿主或应用重启后不丢。
- 模型不能做自己成绩的裁判。它说“已完成”只是声明，不是证据；否则目标模式会退化成“模型自认为
  完成就结束”。
- 目标模式不能改变权限。审批、提问、危险命令拦截照旧；它不是无人值守模式（ADR-0018），不能借
  目标循环绕过审批。
- 循环必须有界。每轮限额之外，还要有目标级轮次与时长预算；应用退出、用户停止、失败和限额都
  不能自动续跑。
- 目标判定本身是一次模型调用。它应当和标题、压缩摘要一样是后台辅助调用：失败不破坏会话，用量
  记 `auxiliary`，不进入上下文圆环。
- 判定者不能调用工具或执行命令。给它工具会把“判定”变成又一次执行，带来权限与副作用问题；它
  只能依据主进程提供的有界证据。

> 本 ADR 的“目标”（session goal）与计划文档里的 `PlanDocument.goal`（这份计划要做什么）不是
> 一回事。代码类型统一用 `Goal*`，界面文案用“目标模式”，避免与计划的“目标”混淆。

## 决定

- **目标是会话级持久状态，不是新的 `PromptMode`，也不是权限模式。** 一个会话同时只有一个未结束
  的目标。新增持久事件 `goal.created`、`goal.paused`、`goal.resumed`、`goal.condition_updated`、
  `goal.evaluated`、`goal.ended`；`SessionView` 增加目标投影。`goal.created` 记录解析后的预算
  （默认最多 20 轮、2 小时活动时长），以后改默认值不影响已有目标；未结束目标可通过
  `goal.condition_updated` 改条件（不中断当前轮）。轮次只统计目标处于活动状态时开始的根轮次，
  暂停期间的用户轮次不消耗目标预算。目标只在 `kind === 'normal'` 的会话可用，试运行与自动修复
  会话不注册该入口。
- **循环在主进程，不在宿主。** 新增 `GoalService`，监听事件日志；只在根运行的 `turn.completed`
  （没有 `parentRunId`）后评估。判定为 `not_met` 时，由主进程通过会话管理器自动发起下一轮；宿主
  只从 `host.prompt` 收到当前目标，用于在系统提示词里说明目标与判定规则，不持有目标状态。
- **判定者是独立的、无工具的辅助补全。** 默认用会话主模型，也可在设置里单独指定判定模型
  （`goalJudgeModel`）；两种情况都走现有 `complete` 路径（与标题、压缩相同），
  专用系统提示词，输出严格 JSON：`met` / `not_met` / `impossible` 加理由与证据引用。输入是主进程
  从事件日志整理的有界证据包：本目标的用户消息与自动续轮消息、助手最终回复、工具调用与结果
  （含退出码与失败原因）、改动文件路径、子运行结果摘要、此前的判定理由。工具输出与对话内容都按
  不可信数据处理。证据只覆盖目标活动期间的轮次、当前保留的对话区间与影响工作区的改动：被回退
  掉的轮次、暂停期间的其他对话、子运行的内部工具输出不进来（只保留子运行的文件改动路径与改动集
  汇总，以及暂停期间的文件改动作为当前工作区状态）。
  无效输出重试一次，仍无效就暂停目标，不猜；判定调用本身有超时。`met` 必须至少引用一条证据。
- **未达成时的续轮是一条带来源标记的持久用户消息。** `message.user` 增加可选 `origin: 'goal'` 与
  `goalId`；内容包含目标提醒、判定理由和“继续并给出可验证证据”的要求。界面把它显示成目标继续条
  而不是普通用户气泡。它是模型历史的一部分，重启重建历史后仍然存在。判定理由只作为不可信的引述
  放进消息，不能盖过系统提示词里的安全规则。用户手动发送的消息优先于自动续轮；自动续轮从不以
  `steer` 注入正在运行的一轮。
- **结束与暂停分开。** `met`、`impossible`、用户清除、预算耗尽是结束；用户暂停、应用重启、运行
  中断、进入计划模式、用户停止当前轮、轮次失败或限额、判定器持续失败、连续多轮没有可验证进展、
  会话归档是暂停。会话删除让目标随事件日志一起消失，不单独写终止事件。暂停保留目标与预算，可由
  用户恢复；结束是终态，用户要重新开始需新建目标。应用重启后恢复为暂停，不自动续跑，避免无人
  盯着时消耗 token。
- **过期的判定不生效。** 判定是一次异步模型调用，期间用户可能暂停、清除、回退、恢复检查点、发送
  新消息，甚至新建目标。判定结果写事件前校验目标代际与最新轮次；过期结果只保留用量，不改变目标
  状态、不自动续轮。
- **循环有进展刹车。** 连续若干**自动续轮**既没有文件改动、也没有成功的写入 / 执行结果时，不等
  预算耗尽就暂停并说明“没有可验证进展”；用户手动发起或中途引导的轮次会清零计数，恢复后重新
  计数。后台命令尚未退出不算完成证据。
- **权限完全不变。** 目标轮是普通的交互运行：审批仍然弹卡片等待，`ask_user` 仍然等待回答，强制
  拦截仍然生效。目标循环没有“始终允许”，也不提供无人值守选项；自动修复仍是无人值守的唯一入口。
- **`/goal` 与只读计划轮互斥。** 目标活动时开始一个只读计划轮会先暂停目标；计划批准或拒绝后不
  自动恢复，需用户 `/goal resume`。`goal.set` 与 `goal.resume` 都拒绝存在待审计划的会话，避免
  目标循环绕过计划审批。批准计划触发的执行轮按普通轮次运行，但目标仍保持暂停、不注入目标；
  执行结束后用户再恢复目标。
- **回退、压缩、归档的边界。** 对话回退（ADR-0046）、撤销本轮、恢复检查点、整文件或按块撤销都会
  改变对话或工作区，活动目标暂停；如果目标创建于回退区间内，或它的第一条用户消息被编辑，投影里
  目标消失，`GoalService` 同步停止。重新生成保留目标但暂停。压缩不影响目标：条件每轮都注入系统
  提示词，判定证据从事件日志重建并跳过回退区间，不依赖压缩后的摘要。归档会话暂停目标；删除会话
  让目标随事件日志一起消失。

## 备选方案

- **把目标做成 `PromptMode: 'goal'`**：模式是单轮输入的一部分，而目标要跨轮持续、在休止时仍可
  查看/暂停/恢复，还要在重启后恢复。放进模式会让 `session.prompt`、工具可见性和宿主的单轮状态
  都承担持久状态，否决。
- **让模型自己调用 `goal_done` 或在回复里宣布完成**：这仍然只是模型的声明；不独立核验就无法阻止
  “感觉差不多了”就停。以后可以作为判定者的辅助信号，但不能作为唯一判据。
- **判定者带工具，自己去跑测试/读文件**：判定变成第二次执行，需要权限、审批、超时和副作用处理，
  而且可能与主运行互相干扰。第一版只做无工具判定；证据由主运行产出并由主进程整理。
- **循环放在宿主**：宿主是按运行启动的进程，没有存储、设置和跨轮调度；应用重启后宿主消失。主进程
  已经有会话队列、模型解析、事件写入与预算限制，放在主进程不需要新的事实来源。
- **和计划模式合并：批准计划后自动循环到达成**：把“对齐”和“终止条件”混在一起。计划批准只是允许
  执行，用户仍可能想逐步检查；自动执行到底会让计划模式的审批失去意义。第一版保持两者独立。
- **允许无人值守目标循环**：会绕过审批与提问的交互前提，和 ADR-0018 的无人值守策略混淆；自动修复
  已经覆盖那条路径。否决。

## 后果

- 新增 5 个持久事件、1 个可选的消息来源字段、1 个可选的 `host.prompt` 字段，以及 4 个会话 IPC
  方法；事件版本不升（只追加可选字段与新事件类型）。旧界面收到未知事件时按既有规则推进 `seq`，
  不会崩溃，但看不到目标条，因此功能随界面一起发布。
- 每次目标轮之后多一次判定模型调用；用量计入会话统计但标记 `auxiliary`。判定默认使用会话主模型，
  也可以单独设置，便于控制成本或加强判定独立性。默认最多 20 轮、2 小时
  活动时长；应用重启自动暂停，暂停时间不把应用关闭期间算进去。等待审批 / 提问与系统休眠都计入
  活动时长，所以 2 小时是墙钟安全上限而不是模型实际工作时间。用户仍应把条件写成可验证的结果，
  而不是“把某模块改好”这类无法判定的动作；条件不可验证时循环会跑到轮次或时长上限。
- 判定质量取决于证据包和提示词。证据不足时判定返回 `not_met` 并给出下一步验证建议，循环可能因此
  多跑一两轮；判定持续失败会暂停而不是无限重试。用户可以在目标面板里查看每次判定与证据，发现
  误判可暂停或清除。
- 目标预算在轮次边界检查。单轮自身的步数、token、时长仍由运行限额和用户停止控制；目标模式不会
  在一个正在进行的轮次中间强行截断。
- 目标不会在应用退出后继续运行，也不跨会话；定时/后台目标留给无人值守与自动化阶段，不在本 ADR
  范围内。
