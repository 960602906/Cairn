# ADR-0046 消息编辑重发与重新生成：追加式回退事件

- 状态：已接受（实施）
- 日期：2026-11-19
- 相关决策：ADR-0005（事件日志是事实来源）、ADR-0008（检查点只管工作区）、ADR-0027（压缩不改原始事件）
- 相关文档：[Agent Runtime](../design/agent-runtime.md)、[聊天区域状态显示](../plan/chat-status-display.md)

## 背景

聊天区域此前只能“复制本轮回复”和“撤销本轮”——后者只恢复工作区文件，对话记录保留。
用户需要两类常见的对话操作：

- **编辑重发**：改一条用户消息，从这条消息开始重新对话；
- **重新生成**：保留用户输入，重新生成这一轮的回复。

约束：

- 事件日志只追加（ADR-0005），不能删除或改写已落库的事件；界面是事件的投影。
- 宿主在内存里持有对话历史；只改主进程的事件日志而不重启宿主，模型仍会看到被丢弃的轮次。
- 检查点是工作区快照，与对话记录是两条独立的线；回退对话不应隐式撤销文件。
- 父运行、子运行、计划、待办、检查点、用量都挂在 `seq` 或 `turnId` 上，回退必须一并收敛。

## 决定

- **新增持久化事件 `conversation.rewound`**：`{ fromSeq, reason: 'edit' | 'regenerate' }`。
  事件本身留在日志里，回退区间是 `[fromSeq, 本事件 seq)`；投影与重建历史都跳过这段区间。
  工作区文件不受影响。
- **回退点是这一轮的第一条用户消息**。编辑只能指向轮次开头的用户消息；重新生成接受这一轮的
  任意消息，主进程据此找到轮次开头。这一轮和之后的轮次一起丢弃，不做对话分支/树。
- **宿主必须重启**：回退后即使宿主还空闲在跑，也先停掉它；下一次输入按事件日志重建历史
  （`rebuildHistory` 已跳过被回退的区间），模型不会再看到被丢弃的轮次。
- **重新生成复用原始输入**：按事件日志里原 `message.user` 的完整 payload（含 `@` 引用展开的
  `context`）重发，保证模型看到的内容与上一轮一致。编辑则按新文本在网关重新展开
  `@` 文件引用、`/技能名` 与 `@Agent名`。
- **只在空闲时允许**：进行中的一轮、排队的输入或撤销锁定时返回 `run.busy`；正在运行的一轮
  不能回退。
- **视图同步收敛**：消息、检查点、恢复、计划、待办、审查循环、流水线、工具、进行中消息与
  用量按 `seq` / `turnId` 过滤；回退点之后创建的子运行移除；被回退轮次的用量从会话累计中扣除。
- **确认框说明后果**：有后续轮次时先确认；文案明确“工作区文件不会自动撤销”。

## 考虑过的备选

- **对话分支（每次编辑分叉）**：表达能力更强，但需要树形视图、分支切换、分支级压缩与用量，
  与当前线性会话、侧栏与活动中心的模型冲突，暂不做。
- **删除事件**：与只追加的事件日志和压缩的原始事件保留原则（ADR-0027）冲突，也让审计与诊断
  失去依据。
- **复用检查点恢复实现**：检查点恢复工作区文件且明确不截断对话（M1 的约定），语义相反；
  只在“回退后是否自动撤销文件”上做选择也违背最小惊讶原则。

## 后果

- 日志只增不减；被回退的事件仍可审计，重建历史与投影必须始终跳过回退区间。
- 所有消费事件的地方都要认识新事件类型；旧版本界面收到未知事件时按既有规则只推进 `seq`，
  不会崩溃，但也不会隐藏被回退的消息——因此该事件随功能一起发布。
- 回退不会撤销文件；想同时恢复工作区，仍使用轮次操作里的“撤销本轮”（检查点）。
- 用量在投影里扣除被回退轮次，但不改写历史事件；活动中心等按运行聚合的统计可能略高于会话内
  显示，这是保留审计记录的有意取舍。
