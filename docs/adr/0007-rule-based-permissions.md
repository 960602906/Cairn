# ADR-0007 基于规则的权限引擎

- 状态：已接受
- 日期：2026-11-02

## 背景

最初方案只有"只读、询问、自动"三种权限模式。实际使用中很快会需要更细的控制，例如"允许 `npm test` 但每次询问 `npm install`""禁止读取 `.env`"。如果三种模式被写死在审批逻辑里，后续加细粒度规则需要重写审批流程。第一版就开放命令执行，权限设计尤为重要。

## 决定

- 权限由规则表示：`scope`（global / project / session）、`effect`（allow / ask / deny）、`match`（工具名、类别、路径 glob、命令模式）、`source`（预设 / 用户 / 审批时选择）。
- 判定顺序：强制拦截 → 匹配规则取最严格结果（deny > ask > allow）→ 无匹配时按工具类别默认值。
- 低范围的 allow 不能覆盖高范围的 deny。
- 三种模式只是三组预设规则。
- 审批时用户可选择"本会话或本项目始终允许"，自动生成对应规则。
- 权限引擎是 `packages/core` 中的纯函数，便于完整的单元测试。

## 备选方案

- **固定三种模式**：实现简单，但扩展困难。
- **完全由模型自行判断风险**：不可控，容易被提示注入绕过。

## 后果

- 需要规则管理界面（M3），以及清晰的"为什么被拦截"说明。
- 危险命令识别基于模式匹配，可以被绕过，因此只作为安全网而非安全边界，真正的隔离依靠后续沙箱。
