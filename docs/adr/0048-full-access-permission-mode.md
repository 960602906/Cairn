# ADR-0048 完全访问权限模式

- 状态：已接受（实施）
- 日期：2026-11-25
- 相关决策：ADR-0007、ADR-0028、ADR-0034、ADR-0045
- 相关文档：[架构 §10](../architecture.md#10-权限与审批)；[管理界面 §4](../design/agent-management-ui.md)

## 背景

三种权限模式里最宽松的“自动”仍会对危险命令（`git push`、`sudo`、递归删除）与敏感文件（`.env`、
私钥）再次询问，部分破坏性命令直接拒绝（ADR-0007）。这是防误操作的安全网，但用户在某些任务里
（例如在一次性容器、隔离 worktree 或完全由自己控制的脚本仓库里）需要“无论做什么都不再询问”的
模式。缺少这一档时，用户只能在审批卡片上反复点允许，或者手动堆叠大量 `allow` 规则。

约束：

- 强制拦截在规则之前执行，单纯添加 `allow` 规则覆盖不了它；
- 计划模式是用户显式要求的只读轮次（ADR-0028），不能因为权限模式而变成可写；
- 沙箱（ADR-0034）是执行隔离，权限模式只决定“问不问、拦不拦”，不应顺带改变沙箱档位；
- 用户手动添加的 `deny` 规则是明确意图，不应被一个预设模式悄悄推翻；
- Agent 的权限预设只能收紧全局设置，不能放宽（ADR-0029）。

## 决定

- **新增第四种模式 `full-access`（完全访问）。** 与前三种一样是全局设置，输入框与设置页都可以
  切换，切换后运行中的会话立即生效。
- **预设规则是一条放行所有调用的 `allow`。** 匹配条件为空，写入、执行、联网、委派与第三方工具都
  不再按类别默认值询问；用户自定义的 `deny` 规则仍然按 `deny > ask > allow` 生效，保存的 `ask` 规则
  在完全访问下按放行处理（否则仍会弹审批）。
- **跳过除计划模式外的全部强制拦截。** 危险命令、敏感文件、沙箱不可用时的拒绝或询问、Agent 的
  写入路径白名单、委派目标审批与自动修复的 Git 工具守卫都不再参与判定。计划模式的只读守卫与待办
  列表守卫保留。
- **沙箱照常执行。** 模式只跳过沙箱守卫的询问与拒绝，命令仍按设置里的档位与能力运行；完全访问
  不等于关闭沙箱，也不自动切到 `danger-full-access`。
- **Agent 可以选完全访问，但不会超过全局模式。** Agent 预设仍然只收紧、不放宽；全局不是完全访问
  时，选了完全访问的 Agent 与“询问”一样按类别默认值判定。只读 Agent 在全局完全访问下仍然只读。
- **模式随规则一起下发。** `host.init` 与 `host.permissions.update` 增加可选的 `permissionMode`，
  宿主据此决定是否跳过守卫；旧主进程省略时按“询问”处理。规则仍然完整下发，宿主不自行推导模式。

## 备选方案

- **只跳过 `ask`、保留硬性拒绝**：用户要的是“无论做什么都不需要询问”，被直接拒绝的破坏性命令
  同样属于不再确认的范围；保留会让 `rm -rf /` 之类在完全访问下仍然失败。否决。
- **用规则表达完全访问**：强制拦截先于规则执行，规则本身无法关闭守卫；要么改判定顺序（削弱所有
  模式的安全网），要么在引擎里加特殊规则标记（隐式且难以审计）。否决。
- **每个会话单独选择**：需要持久化、恢复与会话切换逻辑；先做全局设置，后续需要时再扩展。
- **完全访问同时关闭沙箱**：把两个独立的安全维度绑在一起，用户无法只关审批而保留隔离。否决。
- **让 Agent 的完全访问覆盖全局**：违反“Agent 只能收紧”的既有约束，也会让导入的 Agent 定义
  悄悄放宽用户设置。否决。

## 取舍与后果

- 与 ADR-0034 的“`danger-full-access` 必须逐次确认”冲突：完全访问下不再逐次确认。这是用户主动
  选择的全局模式；沙箱仍按设置执行，隔离级别不会被模式改变。
- 审批安全网失效：完全访问下模型可以直接执行危险命令、读写敏感文件、越过 Agent 的写入路径限制。
  设置页在选中该模式时显示风险提示，输入框的菜单也说明“不再询问”。
- 计划模式仍只读；用户手动添加的 `deny` 规则仍然生效，可以用它兜住个别路径或命令。保存的 `ask`
  规则不再询问，需要保留确认时应在完全访问之外使用。
- 协议、宿主、主进程、界面与测试都增加第四种取值；模式切换通过 `host.permissions.update` 即时
  生效，不需要重启宿主。
- 危险命令识别本来就只是安全网而非安全边界（架构 §10.5）；完全访问把“防误操作”完全交给用户。
  需要强隔离时仍应使用沙箱或隔离工作区，而不是依赖权限模式。
