# ADR-0034 Windows 命令沙箱

- 状态：提议（M5-00 草案；M5-04/05 定稿）
- 日期：2026-11-10
- 相关决策：ADR-0007、ADR-0012、ADR-0035、ADR-0036
- 预研证据：[M5-00 预研报告](../plan/m5-spikes.md) §3；[`spikes/m5`](../../spikes/m5/README.md)

## 背景

现有命令执行已经有审批、路径校验、环境清洗与 Job Object 进程树清理，但这些机制不是 OS 级隔离：一旦命令被允许，它仍能以应用用户身份写工作区外文件、读取用户配置并访问网络。M5 需要在“按用户安装、无需管理员”的约束下，提高命令的隔离边界，同时不破坏常见开发命令。

候选方案：

1. 保持现状，只增加提示；
2. 受限令牌 + 低完整性 + 工作区 ACL；
3. AppContainer + 工作区 ACL；
4. 虚拟机或容器。

方案 1 不能兑现发布目标；方案 4 体积、启动成本与文件系统映射不适合桌面 Agent。

## 决定

- **默认档位是 `restricted-workspace`。** 使用 `CreateRestrictedToken` 禁用最大权限与 LUA，结合低完整性级别、Job Object 与工作区 ACL。工作区可写；工作区外、系统目录与其他用户目录写入被拒绝；默认不授予管理员能力。
- **网络不隔离，必须诚实标注。** 受限令牌下网络仍可用，预研中本机回环、HTTPS 与 `pnpm install` 均成功。界面、设置、审批、事件与诊断必须写“网络未隔离”，不得把该档位描述成网络沙箱或恶意代码安全边界。
- **AppContainer 不作为默认档位。** 预研中 AppContainer 能创建工作区、阻断越界写与默认网络，但用户目录中的 `node`、`pnpm`、`python`、`rg`、Git、TypeScript 工具链无法启动，不满足 go 门槛。仅保留实验/诊断实现，未经重新验收不得设为默认。
- **沙箱失败默认关闭。** 创建受限令牌、设置完整性、授予 ACL 或启动进程任一步失败时，不静默回退到无沙箱执行。用户必须显式选择“本次不使用沙箱”，该选择写入事件，并遵守现有权限审批。
- **保护范围仅限命令进程树。** `run_command` 与 `start_command` 启动的进程树在沙箱内；MCP 服务、Agent 宿主、主进程与它们的子进程不在命令沙箱内。文档与界面必须区分“命令沙箱”和“整个应用隔离”。
- **保持现有命令语义。** 沙箱不改变 shell 选择、UTF-8 编码、退出码、超时、取消、环境清洗与 Job Object 终止语义；只改变进程令牌、完整性、ACL 与网络能力。
- **显式升级。** `danger-full-access` 必须逐次或按会话审批，不能持久化为默认；计划模式与只读 Agent 强制只读沙箱，不能靠权限预设放宽。
- **只读档位。** `read-only` 通过 ACL/令牌限制工作区写入，临时目录仍可写；具体实现由 M5-04 定稿。
- **能力探测用于诊断。** 启动时探测创建受限令牌、设置完整性、Job Object 与网络状态，结果写入诊断包，不包含项目内容、用户名或凭据。

## 备选方案

- **AppContainer 默认**：隔离更强，但真实开发工具链不可用，否决。
- **只增加提示，不做 OS 隔离**：实现成本低，但无法兑现 M5 目标，否决。
- **虚拟机/容器**：隔离最强，但与本地工作区、性能、安装体积和按用户安装冲突，M5 不做。
- **Windows Filtering Platform 网络隔离**：可能补足网络边界，但需要驱动/服务权限与额外兼容性验证，不在 M5-00 结论内；未来可单独评估。

## 后果

- 受限令牌只能阻止写入与管理操作，不能阻止读取用户可读文件或访问网络；这是明确的、可见的安全边界，不是“无懈可击”的沙箱。
- AppContainer 代码与探测结果仍保留，但默认路径不使用；后续版本若工具链兼容性改善，可重新评估。
- 用户会遇到“命令需要网络/需要写工作区外”的审批与升级流程；错误信息必须给出具体原因与下一步。
- 真实标准用户、Windows 10 与中文用户名场景尚未验证，M5-10 必须补齐；未通过前不得宣称正式支持。
