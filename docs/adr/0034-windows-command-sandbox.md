# ADR-0034 Windows 命令沙箱

- 状态：已接受（M5-00 起草，M5-04 实施；M5-05 接入界面与诊断）
- 日期：2026-11-10
- 相关决策：ADR-0007、ADR-0012、ADR-0035、ADR-0036
- 预研证据：[M5-00 预研报告](../plan/m5-spikes.md) §3；[`spikes/m5`](../../spikes/m5/README.md)

## 背景

现有命令执行已经有审批、路径校验、环境清洗与 Job Object 进程树清理，但这些机制不是 OS 级隔离：一旦命令被允许，它仍能以应用用户身份写工作区外文件、读取用户配置并访问网络。M5 需要在“按用户安装、无需管理员”的约束下，提高命令的隔离边界，同时不破坏常见开发命令。

候选方案：

1. 保持现状，只增加提示；
2. 受限令牌 + 低完整性 + 工作区 ACL；
3. AppContainer + 工作区 ACL；
4. 虚拟机或容器。

方案 1 不能兑现发布目标；方案 4 体积、启动成本与文件系统映射不适合桌面 Agent。

## 决定

- **默认档位是 `restricted-workspace`。** 使用 `CreateRestrictedToken` 禁用最大权限与 LUA，结合低完整性级别、Job Object 与工作区 ACL。工作区可写；工作区外、系统目录与其他用户目录写入被拒绝；默认不授予管理员能力。
- **网络不隔离，必须诚实标注。** 受限令牌下网络仍可用，预研中本机回环、HTTPS 与 `pnpm install` 均成功。界面、设置、审批、事件与诊断必须写“网络未隔离”，不得把该档位描述成网络沙箱或恶意代码安全边界。
- **AppContainer 不作为默认档位。** 预研中 AppContainer 能创建工作区、阻断越界写与默认网络，但用户目录中的 `node`、`pnpm`、`python`、`rg`、Git、TypeScript 工具链无法启动，不满足 go 门槛。仅保留实验/诊断实现，未经重新验收不得设为默认。
- **沙箱失败默认关闭。** 创建受限令牌、设置完整性、授予 ACL 或启动进程任一步失败时，不静默回退到无沙箱执行。用户必须显式选择“本次不使用沙箱”，该选择写入事件，并遵守现有权限审批。
- **保护范围仅限命令进程树。** `run_command` 与 `start_command` 启动的进程树在沙箱内；MCP 服务、Agent 宿主、主进程与它们的子进程不在命令沙箱内。文档与界面必须区分“命令沙箱”和“整个应用隔离”。
- **保持现有命令语义。** 沙箱不改变 shell 选择、UTF-8 编码、退出码、超时、取消、环境清洗与 Job Object 终止语义；只改变进程令牌、完整性、ACL 与网络能力。
- **显式升级。** `danger-full-access` 必须逐次或按会话审批，不能持久化为默认；计划模式与只读 Agent 强制只读沙箱，不能靠权限预设放宽。
- **只读档位。** `read-only` 通过 ACL/令牌限制工作区写入，临时目录仍可写；具体实现由 M5-04 定稿。
- **能力探测用于诊断。** 启动时探测创建受限令牌、设置完整性、Job Object 与网络状态，结果写入诊断包，不包含项目内容、用户名或凭据。

## 实施记录（M5-04）

- **默认机制是受限令牌。** M5-00 的结论是 AppContainer 下用户目录中的 Node、pnpm、Git 等工具链无法启动，因此默认路径使用 `CreateRestrictedToken`（禁用最大权限与 LUA）+ 低完整性 + Job Object；AppContainer 代码、能力探测与清理保留为实验档位，只由 `CAIRN_SANDBOX_MECHANISM=appcontainer` 开启，不因“探测可用”自动启用。
- **只读档位用完整性标签实现。** `workspace-write` 把工作区目录设为低完整性（`icacls /setintegritylevel (OI)(CI)L`），低完整性进程可写；`read-only` 设为中完整性（`M`），低完整性进程无法写入。没有删除或重写工作区 ACL，避免破坏用户既有权限；专用临时目录始终为低完整性。
- **网络如实标注。** 受限令牌不能隔离网络，`SandboxExecution.networkIsolated` 始终为 false，界面、设置、事件与诊断必须写“网络未隔离”。AppContainer 才按 `none` / `internet` / `private` 授予 `S-1-15-3-1` / `S-1-15-3-3`。
- **失败关闭是唯一默认。** 能力不可用、执行器创建失败或任一准备步骤失败都会拒绝启动命令，并在事件里写 `mechanism: none` 与原因；只有用户把设置改为 `ask` 并逐次审批后，命令才以应用用户权限运行。
- **`danger-full-access` 每次审批。** 该档位不能被持久化为默认值，且权限守卫把它实现为不可覆盖（`overridable: false`）的逐次审批，用户不能通过“始终允许”静默放行。
- **计划模式与只读 Agent。** 计划模式已由 `planModeGuard` 拒绝全部执行与写入类工具，因此不需要为单轮切换可变沙箱策略；只读 Agent 在 `host.init` 被强制为 `read-only` 策略，不依赖用户权限预设。
- **保护范围与命名。** 沙箱只覆盖 `run_command` 与 `start_command` 的进程树；AppContainer 名称由安装标识的 SHA-256 摘要生成，不含项目路径、用户名或凭据。
- **未完成部分。** 真实标准用户、Windows 10、干净 VM 与中文用户名的验证留给 M5-10；设置页、审批文案、终端标记与诊断包字段由 M5-05 接入。本地真实命令矩阵通过不等于这些环境已验证。

## 实施记录（M5-05）

- **协议。** 新增 `SandboxStatus`（平台、选择的机制、策略、不可用行为与实际能力）与 `sandbox.status` 请求；审批请求增加可选的 `sandbox` 与 `overridable`；`ToolCallView` 与诊断摘要增加沙箱字段。旧事件、旧审批与旧客户端不受影响。
- **统一文案。** `sandbox-labels.ts` 由 `SandboxExecution` 生成“沙箱：档位 · 网络”或“未沙箱化：原因”；受限令牌与 `danger-full-access` 一律显示“网络未隔离”。`SandboxBadge` 在终端卡片、工具时间线与审批卡片共用；未生效时使用错误色并给出原因，避免把“无网络策略”误读成“网络已隔离”。
- **审批。** 审批卡片显示这条命令实际使用的档位、机制与网络状态；`overridable: false`（`danger-full-access`、沙箱不可用回退）时不显示“始终允许”，数字键 2 也不生效，防止用户把沙箱升级静默保存成规则。
- **设置。** 设置页新增命令沙箱分组：默认档位（只读 / 工作区可写）、网络策略（无网络 / 公网 / 本地网络）、不可用行为（拒绝 / 每次询问）与能力状态。能力状态显示实际机制、回退说明、四项探测结果与网络状态；探测失败提示导出诊断包。不提供“永久关闭沙箱”的一键开关。
- **诊断。** `DiagnosticsSummary.sandbox` 与 `sandbox.json` 记录平台、机制、策略、不可用行为与能力探测；不包含项目内容、用户名或凭据。导出清单只在采集器存在时列出该文件。
- **错误码。** AppContainer 创建、派生与空标识失败使用 `sandbox.appcontainer_failed`，与 `sandbox.setup_failed`、`sandbox.spawn_failed` 区分。
- **测试。** 组件测试覆盖徽标（生效 / 未生效 / 网络是否隔离 / 未知原因）、审批不可覆盖、终端与时间线、设置页加载 / 失败 / 回退 / 不可用、诊断弹窗与 `sandbox.json`；权限与流水线测试覆盖 `overridable` 传播。e2e 覆盖设置页切换、审批卡片标记，并在 Windows 且能力可用时用真实命令验证工作区写入成功、工作区外写入被拒绝。非 Windows 平台在命令沙箱不生效时按原有语义运行，e2e 明确跳过真实隔离用例。
- **边界。** 沙箱仍只覆盖 `run_command` / `start_command` 的进程树；受限令牌不隔离网络；干净 VM、标准用户、Windows 10 与中文用户名留给 M5-10。

## 备选方案

- **AppContainer 默认**：隔离更强，但真实开发工具链不可用，否决。
- **只增加提示，不做 OS 隔离**：实现成本低，但无法兑现 M5 目标，否决。
- **虚拟机/容器**：隔离最强，但与本地工作区、性能、安装体积和按用户安装冲突，M5 不做。
- **Windows Filtering Platform 网络隔离**：可能补足网络边界，但需要驱动/服务权限与额外兼容性验证，不在 M5-00 结论内；未来可单独评估。

## 后果

- 受限令牌只能阻止写入与管理操作，不能阻止读取用户可读文件或访问网络；这是明确的、可见的安全边界，不是“无懈可击”的沙箱。
- AppContainer 代码与探测结果仍保留，但默认路径不使用；后续版本若工具链兼容性改善，可重新评估。
- 用户会遇到“命令需要网络/需要写工作区外”的审批与升级流程；错误信息必须给出具体原因与下一步。
- 真实标准用户、Windows 10 与中文用户名场景尚未验证，M5-10 必须补齐；未通过前不得宣称正式支持。
