# ADR-0026 MCP 连接放在主进程，宿主经 RPC 调用

- 状态：已接受
- 日期：2026-11-07
- 相关：[ADR-0017](0017-unified-capability-layer.md)、[ADR-0010](0010-credential-provider.md)、[Agent Runtime 第 21.3 节](../design/agent-runtime.md#213-mcp)

## 背景

MCP 服务可能是本地子进程（stdio），也可能是远程地址（Streamable HTTP）。连接需要长期保持、断线重连、超时、日志与凭据，而 Agent 宿主每个会话一个进程，会随空闲回收。

如果把连接放在宿主里：

- 每个会话都会单独启动一份 MCP 子进程，资源浪费且状态不一致；
- 凭据需要重复下发到多个宿主；
- 连接日志分散，界面难以汇总；
- 服务状态与工具列表无法跨会话复用。

## 决定

- MCP 连接管理器（`packages/mcp`）与 `mcp-service` 放在**主进程**。应用启动时连接已启用的服务；服务断开时按退避重连；退出时关闭子进程。
- 宿主在 `host.init` 中拿到当前可用工具的**定义**（名称、描述、JSON Schema、类别），不拿到传输配置或凭据。
- 宿主执行 MCP 工具时经 `host.mcp.call` 请求主进程，由主进程调用 SDK；结果按工具输出预算截断后返回。
- 服务断开时其工具从下一轮起不再下发；进行中的调用返回 `mcp.not_connected`。
- 环境变量值与认证令牌只存凭据服务（ADR-0010）；`mcp_servers` 表只保存变量名与凭据引用。日志按这些值脱敏。
- 工具名统一为 `mcp_<服务名>_<工具名>`，只保留 `[a-z0-9_-]`，超过 64 个字符截断并保证唯一。模型接口普遍不接受 `.`，因此没有使用设计稿中的 `服务名.工具名` 字面形式，但保持“服务前缀 + 工具名”的语义。
- MCP 工具的 `source` 为 `{ kind: 'mcp', serverId }`，`trust` 为 `third-party`；默认类别 `network`、默认效果 `ask`，用户可按工具覆盖。

## 备选方案

- **连接放在宿主**：与资源、凭据和日志的集中管理冲突，多会话时重复启动服务。
- **主进程代执行但把连接配置随 `host.init` 下发**：会把令牌暴露给宿主，违背 ADR-0010。
- **工具名保留点号**：部分模型接口会拒绝，且与现有 `TOOL_NAME_PATTERN` 冲突。

## 后果

- 主进程需要维护连接生命周期与状态事件（`mcp.status`）。
- 宿主与主进程之间多一次 RPC 往返；工具结果需要序列化，图片与资源内容先转成文本摘要。
- MCP 服务不可用不会拖垮宿主；下一轮自动使用最新工具列表。
