# ADR-0018 交互运行与无人值守运行

- 状态：已接受
- 日期：2026-11-02
- 详细设计：[Agent Runtime 详细设计第 23 节](../design/agent-runtime.md#23-交互运行与无人值守运行)

## 背景

以后可能加入定时任务、事件触发等自动化功能。此时没有用户在场，权限引擎返回"询问"时无法弹出审批。如果第一版的运行和权限逻辑都假设"用户一定在场"，加入自动化时需要修改状态机和权限判定。

## 决定

- 运行增加 `mode` 字段：`interactive`（交互）或 `unattended`（无人值守）。
- 无人值守运行遇到"询问"时按任务配置处理：`deny`（默认，视为拒绝）或 `pause`（暂停，等用户下次打开应用时审批）。
- 无人值守运行使用更严格的默认限额，强制拦截类规则一律直接拒绝。
- 第一版只有交互运行，但字段和判定逻辑按两种模式实现并测试。

## 备选方案

- **自动化时直接放行所有操作**：不安全。
- **以后再加**：需要改动权限引擎和状态机，影响已有测试和数据。

## 后果

- 权限引擎的输入增加运行模式，测试用例增加一个维度。
- 自动化功能以后可以在不改动 Runtime 的前提下实现。
