# ADR-0014 只使用宽松许可证的依赖

- 状态：已接受
- 日期：2026-11-02

## 背景

项目暂时私有，后续计划开源，开源时的许可证尚未确定（倾向 MIT 或 Apache-2.0）。如果私有期间引入了 GPL、AGPL 等强著佐权（copyleft）许可证的依赖，开源时可能被迫选择特定许可证或替换依赖。

## 决定

- 直接和间接依赖只允许 MIT、Apache-2.0、BSD、ISC 等宽松许可证。
- 在 CI 中加入许可证检查脚本，出现不在白名单内的许可证时构建失败。
- 随应用打包的外部二进制（如 ripgrep、Git）单独登记许可证，并在开源前确认分发合规。

## 备选方案

- **开源时再统一检查**：可能面临大量替换工作。

## 后果

- 选型时少数依赖可能因许可证被排除。
- 开源时只需选择项目自身的许可证并补充第三方声明。

## M5 变更（草案，M5-03 定稿）

M5 开始随 Windows 安装包分发裁剪版 MinGit（GPLv2）。它不是 npm 依赖，不能从包许可证信息自动推断，必须按外部二进制登记：

- `scripts/bundled-binaries.json` 增加 MinGit 条目：名称、版本 `2.56.0.4`、许可证 `GPL-2.0-only`、作者/来源、固定 SHA256、许可证目录与源码获取说明。
- `scripts/license-exceptions.json` 增加 GPLv2 例外，理由限定为“作为独立程序随应用聚合分发，不链接进本项目代码”；例外不能扩展到其他 GPL 依赖。
- `scripts/licenses/` 增加 GPLv2 全文与源码获取说明；`THIRD_PARTY_NOTICES.txt` 自动包含。
- 安装包内与仓库内都能找到许可证与源码获取方式；CI 许可证检查与第三方声明生成必须覆盖该条目。
- 未完成登记前不得把 MinGit 放进发布包。

本变更在 M5-03 根据正式登记文件与许可证检查结果定稿。
