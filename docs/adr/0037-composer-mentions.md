# ADR-0037 输入框的 `@` 引用

- 状态：已接受
- 日期：2026-11-11
- 相关决策：ADR-0004（AgentRuntime 接口）、ADR-0024（对话风视觉）

## 背景

用户想在消息里直接指明要看的文件或文件夹，而不是让模型自己去找。需要决定：

1. 引用在草稿里怎么表示（富文本里的“块”还是纯文字）；
2. 文件内容在哪里读、怎么交给模型；
3. 历史重建、压缩和界面显示时引用怎么处理。

## 决定

- **草稿里是纯文字 `@路径`。** 开头或空白后面的 `@` 开始一个引用，路径里有空白时写成 `@"路 径"`，可以带行号 `:12` 或 `:12-30`。遇到全角标点断开，末尾的英文标点不算。输入框仍是 `<textarea>` 加高亮层（ADR-0024 的输入框高亮），选中候选只是插入文字，所以手打的引用和选出来的一样生效，撤销、粘贴、输入法都不受影响。分词规则在 `composer-tokens.ts`，消息渲染会共用。
- **候选来自主进程的 `fs.search`。** 参数是 `sessionId`（会话的工作区，隔离工作区时是它自己的目录）或 `projectId`（新对话页还没有会话）。用内置 ripgrep 的 `--files` 列文件：遵守 `.gitignore`，跳过隐藏文件与 `.git`；目录由文件路径推出。列表按根目录缓存 10 秒，最多索引 5 万个文件。空查询列第一层，`目录/` 列下一层，其他按名称精确、前缀、包含，再按路径包含与子序列排序。搜索失败时返回空列表，输入框只显示“没有匹配”。
- **发送时由渲染进程从草稿里解析引用，主进程展开。** `session.prompt` 新增可选的 `mentions: [{ path, lines? }]`（最多 20 个）。网关在交给会话管理器之前读出内容，拼成一段只给模型看的上下文（`<file path="…">…</file>`、`<directory path="…/">…</directory>`），开头一句英文说明这是用户用 `@` 引用的内容。
  - 路径必须是相对路径，词法上和 `realpath` 之后都要在工作区里，符号链接也不能借道越界。读不到、不存在、越界的引用直接忽略，不让整条消息失败。
  - 单个文件内容不超过 32 KB，整条消息不超过 96 KB；超出、二进制或大于 2 MB 的文件只附路径（和行数），提示模型需要时用 `read_file` 去读。目录最多列 200 项。
- **事件里分开存。** `message.user` 新增可选的 `mentions`（展开成功的引用，带 `kind: file | dir`）和 `context`（展开的文字）。界面只显示用户写的内容和引用列表；`context` 不进 `SessionView`。核心的 `userTurnContent` 把 `context` 作为最后一段文字附在输入后面，交给宿主的输入和重建的历史都用它，所以宿主重启或压缩之后模型看到的仍是发送当时的文件内容。

## 后果

- 草稿是纯文字，没有“块”可以整体删除；删一个引用要删掉它的文字。换来的是不引入富文本编辑器、没有新依赖，输入法与撤销行为保持原生。
- 引用的内容是发送那一刻的快照。之后文件再变，模型要自己重新读。
- 文件内容存进了事件日志（受同样的 96 KB 上限约束），会话数据库会随引用变大；诊断包与导出沿用事件日志现有的处理。
- `@Agent`（委派给某个 Agent）与技能指令在后续 PR 里加，复用同一个分词与候选浮层。
