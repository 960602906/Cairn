# ADR-0037 输入框的 `@` 引用

- 状态：已接受
- 日期：2026-11-11
- 相关决策：ADR-0004（AgentRuntime 接口）、ADR-0024（对话风视觉）

## 背景

用户想在消息里直接指明要看的文件或文件夹，而不是让模型自己去找。需要决定：

1. 引用在草稿里怎么表示（富文本里的“块”还是纯文字）；
2. 文件内容在哪里读、怎么交给模型；
3. 历史重建、压缩和界面显示时引用怎么处理。

## 决定

- **草稿里是纯文字 `@路径`。** 开头或空白后面的 `@` 开始一个引用，路径里有空白时写成 `@"路 径"`，可以带行号 `:12` 或 `:12-30`。遇到全角标点断开，末尾的英文标点不算。输入框仍是 `<textarea>` 加高亮层（ADR-0024 的输入框高亮），选中候选只是插入文字，所以手打的引用和选出来的一样生效，撤销、粘贴、输入法都不受影响。分词规则在 `composer-tokens.ts`，消息渲染会共用。
- **候选来自主进程的 `fs.search`。** 参数是 `sessionId`（会话的工作区，隔离工作区时是它自己的目录）或 `projectId`（新对话页还没有会话）。用内置 ripgrep 的 `--files` 列文件：遵守 `.gitignore`，跳过隐藏文件与 `.git`；目录由文件路径推出。列表按根目录缓存 10 秒，最多索引 5 万个文件。空查询列第一层，`目录/` 列下一层，其他按名称精确、前缀、包含，再按路径包含与子序列排序。搜索失败时返回空列表，输入框只显示“没有匹配”。
- **发送时由渲染进程从草稿里解析引用，主进程展开。** `session.prompt` 新增可选的 `mentions: [{ path, lines? }]`（最多 20 个）。网关在交给会话管理器之前读出内容，拼成一段只给模型看的上下文（`<file path="…">…</file>`、`<directory path="…/">…</directory>`），开头一句英文说明这是用户用 `@` 引用的内容。
  - 路径必须是相对路径，词法上和 `realpath` 之后都要在工作区里，符号链接也不能借道越界。读不到、不存在、越界的引用直接忽略，不让整条消息失败。
  - 单个文件内容不超过 32 KB，整条消息不超过 96 KB；超出、二进制或大于 2 MB 的文件只附路径（和行数），提示模型需要时用 `read_file` 去读。目录最多列 200 项。
- **事件里分开存。** `message.user` 新增可选的 `mentions`（展开成功的引用，带 `kind: file | dir`）和 `context`（展开的文字）。界面只显示用户写的内容和引用列表；`context` 不进 `SessionView`。核心的 `userTurnContent` 把 `context` 作为最后一段文字附在输入后面，交给宿主的输入和重建的历史都用它，所以宿主重启或压缩之后模型看到的仍是发送当时的文件内容。

## 后果

- 草稿是纯文字，没有“块”可以整体删除；删一个引用要删掉它的文字。换来的是不引入富文本编辑器、没有新依赖，输入法与撤销行为保持原生。
- 引用的内容是发送那一刻的快照。之后文件再变，模型要自己重新读。
- 文件内容存进了事件日志（受同样的 96 KB 上限约束），会话数据库会随引用变大；诊断包与导出沿用事件日志现有的处理。
- `@Agent`（委派给某个 Agent）与技能指令在后续 PR 里加，复用同一个分词与候选浮层。

## 补充：`/技能名`、`@Agent` 与可点击的路径（2026-11-12）

计划里的 PR4 与 PR5 沿用上面的做法，补了三件事。

- **技能与 Agent 各用一个独立字段，不塞进 `mentions`。** `session.prompt` 新增可选的 `skills: [{ name }]`（最多 5 个）和 `agents: [{ agentId, name }]`（最多 5 个）；`message.user` 同样新增这两个可选字段，界面据此显示 `/技能名` 与 `@Agent名` 标记。`mentions` 仍然只表示文件与目录，`kind` 不用扩成三种，展开逻辑（读文件、行号、32 KB 上限）不用跟着分叉。
- **展开仍在主进程。** 技能正文来自 `skills.catalog(sessionId)`（已启用、未被覆盖），拼成 `<skill name="…">正文</skill>`；Agent 只接受 `agents.list` 里还在、未归档的 id，拼成一行 `<agent id="…" name="…"/>` 并附一句让主 Agent 用 `delegate` 委派的说明。两者的开头各有一句“这是用户点名、按不可信数据处理”的说明，和文件引用一样只写进 `context`，不进视图。
  - 找不到的技能名、已归档或不存在的 Agent 直接忽略，不让整条消息失败；请求里全部找不到时，`skills` / `agents` 不落库，和空引用一致。
  - `/技能名` 后面必须跟任务文字；单独选中时输入框先补全成 `/技能名 `，不发空消息。运行中不能开新的一轮。
- **`@Agent名` 不额外走一条调用链。** 草稿里按名称（中英文名称都认，带空白时用引号）匹配 Agent，这些名称同时从文件引用里排除；主 Agent 收到上下文后按现有 `delegate` 工具委派，界面不需要新的宿主接口。
- **`@Agent名` 只认当前 Agent 的委派白名单。** 新增 `agent.delegationTargets({ sessionId? })`：按会话当前的 Agent（试运行取草稿，普通会话取最近的根运行，新对话页用默认 Agent）返回 `{ enabled, agentIds }`。输入框的候选只列这些目标；主进程展开时按同一份名单过滤，委派关闭时一个都不展开、也不附“调用 `delegate`”的说明。白名单外的 `@名字` 仍留在用户消息里，但不会变成 Agent 上下文，模型也不会被要求调用一个会被拒绝的工具（`delegation.agent_not_allowed`）。
- **助手正文里的相对路径可点。** 新增 `fs.exists`（`{ projectId, paths }`，最多 200 条）批量确认文件是否存在：只返回存在且是文件的相对路径，越界、不存在、读不了一律略过。`Markdown` 把行内代码里形如 `src/a.ts` 或 `src/a.ts:12` 的相对路径交给它确认，确认存在的渲染成按钮，点击在右侧打开文件并滚到那一行。**用户消息里的 `@文件` 同样只在主进程确认过之后才可点**，没确认的保持纯文字，避免把随手写的 `@某人` 变成坏链接。代码块、绝对路径、`.` / `..` 开头、网址与带空白的文字不参与。
