# ADR-0024 界面采用“对话风”视觉风格

- 状态：已接受
- 日期：2026-11-06

## 背景

M1 只做了验收所需的最小界面，没有任何样式（M1 验收记录：撤销确认框不醒目、助手回复的 Markdown 原样显示、工具卡片层级不清）。M2 开始做正式界面前，需要先定下视觉风格，否则各个页面会各做各的。

讨论中做过四版静态预览，对比了三个方向：

- **编辑器风**（参考 VS Code、Cursor）：文件树、编辑区 diff、底部终端，对话在侧边。密度最高，但对话被挤到边上，Agent 管理、活动中心这类非代码页面放进来很别扭。
- **工作台风**（参考 Linear、Raycast）：三栏，右侧常驻会话详情。信息全，但第一版过于朴素，看起来“像玩具”。
- **对话风**（参考 Claude、ChatGPT 桌面端）：单列居中的对话，工具调用和 diff 在对话流中按需展开。

lan 选择对话风，要求细节向市面上优秀的桌面端看齐，并特别打磨代码区的显示。

## 决定

界面采用**对话风**，气质是专业、冷静、克制。具体规范见[视觉规范](../design/visual-style.md)，要点如下：

- **布局**：侧栏直接铺在窗口底色上，对话区是一张内嵌的圆角“纸面”，靠底色区分层次，不画粗边框。对话单列居中，最大宽度约 700px，输入框悬浮在底部。
- **质感**：0.5px 发丝线加多层柔和阴影；灰阶略带冷调；只有一个强调色（蓝），只用于焦点、选中和运行中，主按钮用近黑色（深色模式下反过来用近白色）。
- **主题**：浅色和深色两套完整令牌，默认跟随系统。
- **字体**：界面用系统字体（Windows 上是 Segoe UI 和微软雅黑），等宽字体用 JetBrains Mono（随应用打包，OFL 许可），并关闭连字。
- **代码区**：代码卡片有标题栏（语言图标、路径、新文件标记、增删行数、复制和换行）、单独的行号列、重点行标记；diff 支持合并和分栏两种视图，改动的词单独加深，未改动的部分折叠；命令输出无论什么主题都用深色终端卡片，显示退出码和耗时；每轮结束汇总本轮改动的文件。
- **工具调用**：在对话流里显示成一条细时间线，正在进行的步骤用流光文字；审批卡片用编号选项，可以用 Enter、Esc 和数字键选择；危险操作的确认框用红色主按钮，写清会发生什么。
- **每轮之间**显示检查点分隔线，每轮下方有“撤销本轮”。
- **不显示价格**：界面上不显示任何金额（会话成本、本月花费、模型单价），也不做预算功能；token 数量可以显示。
- **没有账户**：产品没有登录。侧栏底部显示用户自己配置的模型供应商（官方或第三方中转，以及接口格式）和连接状态，而不是用户头像。
- **设置页**与对话页使用同一套布局：左侧分类（通用与外观、模型供应商、MCP 服务、技能、权限与审批），右侧纸面内容区。

技术选型沿用 ADR-0002（React、Tailwind CSS、shadcn/ui）。设计令牌写成 CSS 变量，Tailwind 主题引用这些变量；shadcn/ui 组件按本规范调整外观。对话流里的代码高亮用轻量的高亮库（预计 Shiki，接入时再评估）；Monaco Editor 只用于需要完整编辑或整文件对比的视图。

## 备选方案

- **编辑器风**：适合专注看代码改动的用户，但与“Agent 平台”的定位不符，且非代码页面难以统一。
- **工作台风（常驻右侧详情栏）**：信息密度合适，但常驻面板占用对话空间。其中有用的信息（上下文占用、检查点、本轮改动）改为按需出现：顶栏的改动摘要、输入框里的上下文圆环、对话流中的检查点分隔线和本轮变更卡片。

## 后果

- [Agent 管理界面设计](../design/agent-management-ui.md)中“窗口最左侧一条窄导航栏（图标 + 悬停提示）”改为侧栏中的带文字入口（新对话、搜索、活动、Agents），设置从侧栏底部进入；其中提到的成本显示不再做。
- 需要打包 JetBrains Mono 字体文件，并在 THIRD_PARTY_NOTICES 中登记。
- 静态预览只作为参考，不进仓库；实现以视觉规范文档为准，预览与文档不一致时以文档为准。
