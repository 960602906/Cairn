# ADR-0001 使用 ADR 记录架构决策

- 状态：已接受
- 日期：2026-11-02

## 背景

项目处于设计阶段，有一批以后很难更改的决定（进程模型、数据格式、接口边界等）。项目后续计划开源，需要让后来者理解"为什么这样设计"，而不仅仅是"现在是什么样"。

## 决定

在 `docs/adr/` 中用编号的 Markdown 文件记录每个重要决策，格式统一为：背景、决定、备选方案、后果。`docs/architecture.md` 描述整体架构并引用相关 ADR。

## 备选方案

- 只维护一份总设计文档：决策理由容易在反复修改中丢失。
- 记录在 issue 或聊天中：分散，难以检索。

## 后果

- 修改重要决策时需要新增 ADR，略增加流程成本，但决策历史可追溯。
