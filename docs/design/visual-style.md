## 1. 原则

- **对话是主场**：对话保持主列；改动、会话要点和完整计划放在右侧会话栏，按标签查看，不挤进消息流。
- **会话详情统一进右侧工作台**：会话里需要进一步查看的内容——文件改动、子 Agent 详情、命令输出、diff、计划、检查器、活动等——只在对话里保留一行或一张紧凑摘要，点击后在右侧会话信息栏的标签中展开。右侧栏是会话详情的统一收纳区，不新增整页路由，也不把详情塞进消息流。
- **专业、冷静、克制**：中性灰为主，只有一个强调色；层次靠底色差、发丝线和柔和阴影，不靠粗边框和大色块。
- **看得清 Agent 在做什么**：每一步工具调用、每一处文件改动、每一条命令输出都有清楚的位置。
- **改了能退回**：检查点和撤销入口在每一轮都看得到；危险操作必须醒目确认。
- **状态不只靠颜色**：同时配图标或文字（例如 ✓ 加“退出码 0”）。

## 2. 布局

```
┌───────────────┬──────────────────────────────────────────────┐
│ ● ● ●  ∿  ▢   │  项目 / 会话标题        [2 个文件 +11 −1] ⟲ ⋯ │
│ ✎ 新对话  ⌃N  │ ┌──────────────────────────────────────────┐ │
│ ⌕ 搜索    ⌃K  │ │                                          │ │
│ ☺ Agents      │ │                                          │ │
│               │ │                                          │ │
│ 项目 A        │ │                                          │ │
│  ◌ 会话一     │ │   ┌──────────────────────────────────┐   │ │
│  ● 会话二     │ │   │ 运行状态条                        │   │ │
│ 项目 B        │ │   │ 输入框                            │   │ │
│  …            │ │   │ 📎 询问      供应商·模型 ◔  ■      │   │ │
│ ┌───────────┐ │ │   └──────────────────────────────────┘   │ │
│ │模型供应商 │ │ └──────────────────────────────────────────┘ │
│ └───────────┘ │                  纸面（--paper）              │
└───────────────┴──────────────────────────────────────────────┘
   侧栏 252px，铺在窗口底色（--chrome）上
```

- 三栏布局：左栏、中间的对话、右侧的会话信息栏。没有单独的图标栏。
- 左栏 252px，底色 `--chrome`：顶部是标志、活动图标与收起按钮，活动图标只在左栏展开时显示，紧挨收起按钮；然后是“新对话 / 搜索对话”两行入口、工作空间与会话列表，底部是“设置”。左栏可以收起，收起后顶栏最左侧只出现“展开侧栏”；`<900px>` 时左栏是抽屉。左栏与纸面只靠底色区分，不画分隔线。
- 纸面 `--paper` 从窗口顶部铺到底部：顶栏、对话、会话信息栏是同一张纸面。顶栏高 48px：左边是项目面包屑与会话标题，右边是会话信息栏开关；Windows / Linux 的系统按钮直接叠在这条顶栏上。
- 会话信息栏 348px，只用一条发丝线和对话分开；`>=1440px` 占布局宽度，更窄时是右侧浮层。默认停在首页：文件树和检查是紧凑预览卡片，点卡片在顶部标签栏打开完整页面。“+”菜单只列固定入口（文件、检查、活动）；改动、概要、计划这类需要从会话内容进一步查看的东西不主动列出来：改动点对话里的“本轮变更”，计划点对话里的计划卡片，由用户从会话区域点进去。左栏“活动”在已打开会话时同样显示在右侧标签里，不再整页替换对话。标签栏最左边是固定的首页按钮，其余标签逐个可关；关掉的标签从“+”菜单重新打开，关掉最后一个标签回到首页而不是收起整栏。切换会话时回到首页并清空标签，面板开合保留当前标签。没有改动集时不显示“改动集 / 文件改动”切换；空状态用居中的小图标加一句说明。
- 计划执行期间，步骤进度以一张浮起的小卡片（`--raise` + `--sh-2`）显示在输入框正上方：标题行是目标与“已完成 / 总数”，可以收起；点目标在右侧打开完整计划；步骤全部完成后卡片消失。
- 对话列最大宽度 840px，左右至少 20px 内边距；输入框最大宽度 880px。
- 左栏顶部：标志、活动图标（待处理数角标）与收起按钮；活动图标只在展开时显示。底部是设置。
- 会话列从上到下：标题与计数、新对话 / 收起、搜索、新建对话、按项目分组的会话列表、底部工作区状态卡。
- 窗口宽度不足 900px 时会话列改为抽屉，图标栏常驻。
- 主题只有三个选项：跟随系统（默认）、浅色、深色。浅色是中性的白灰；深色是板岩（冷蓝黑 + 鸢尾强调色）。只有成功 / 警告 / 危险和 diff 另行用色。旧版本保存的五套彩色配色按明暗归到浅色 / 深色。
- 左栏和会话信息栏的宽度可以拖动边缘调整（左栏 208–420px，会话信息栏 300–720px），方向键微调，双击恢复默认；宽度记在本机。

### 2.1 右侧工作台（会话详情收纳区）

- **定位**：右侧会话信息栏是全应用统一的“详情收纳区”。凡是会话域里“对话中放不下、但需要进一步查看”的内容都放这里；对话本身只负责叙事和摘要。不要为会话详情新增整页页面、弹窗或第二套导航。
- **对话只留摘要**：一轮的多项改动汇总成“本轮变更”，子 Agent 委派显示成一张委派卡片，计划显示成计划卡或执行进度卡。摘要保持一行或一张紧凑卡片，不随详情内容变高。
- **点击摘要进侧栏**：摘要的标题行整行可点，点击后在右侧打开对应标签；标签已打开时直接切换，不重复开。摘要内部的单项仍可就地展开轻量预览（例如点文件名展开该文件的 diff），需要看全量时再进侧栏。
- **侧栏不主动列出会话内容**：改动、概要、计划、子 Agent 详情等“从会话区域点进去查看”的内容，不在右侧首页或“+”菜单里预先摆出入口。用户从对话里的摘要卡片点进去；右侧只保留文件、检查、活动三个固定入口。
- **首页只放长期入口**：右侧首页只保留长期存在的入口（文件树、检查），临时或事件型内容（改动、概要、计划、子 Agent、命令输出等）不占首页卡片。
- **跨会话才整页**：只有跨会话的全局视图保留整页形态（如未打开会话时的活动中心、设置页）。左栏“活动”在已打开会话时显示在右侧标签里；从活动跳到其他会话后自动收起活动面板。
- **实现约定**：每个面板是独立组件，只从 `SessionPanelContext` 取会话数据，不依赖外层页面状态。同一内容需要整页与侧栏两种形态时，把主体抽成公共内容组件（参考 `ActivityContent`）。新增面板只需两步：
  1. 新建独立内容组件；
  2. 在 `apps/desktop/src/renderer/SessionPanels.tsx` 的 `SESSION_PANEL_DEFINITIONS` 注册 `id`、短标签、完整标签、`addable` 和内容组件；从对话打开的面板把 `addable` 设为 `false`。
  标签栏、关闭按钮和“+”菜单会自动带上新面板，不需要改侧栏外壳。
- **命名**：标签用 2–4 字的短名；完整名用于无障碍标签和关闭按钮。中英文文案都要补齐。
- **判断标准**：如果一项内容在对话里只能显示摘要、展开后会明显改变消息流的高度或宽度，就做成右侧面板；不确定时优先收纳到右侧，而不是塞进消息流。

## 4. 字体与字号

- 界面字体：`-apple-system, "PingFang SC", "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", system-ui, sans-serif`，不内置界面字体。
- 等宽字体：`"JetBrains Mono"`（随应用打包），回退 `"Cascadia Code", Consolas, Menlo, monospace`。所有代码、路径、命令关闭连字（`font-variant-ligatures: none`），`=>` 不能显示成箭头。
- 数字列和计数用等宽数字（`font-variant-numeric: tabular-nums`）。

| 用途 | 字号 / 行高 | 字重 |
|---|---|---|
| 设置页标题 | 22px | 600 |
| 对话框标题 | 17px | 600 |
| 回复中的小标题 | 16px | 600 |
| 对话正文（用户和助手） | 15px / 1.78 | 400 |
| 侧栏、按钮、工具步骤 | 13.5px | 400，选中 500 |
| 代码、diff | 13px / 22px | 400 |
| 终端输出 | 12.5px / 21px | 400 |
| 说明、时间、计数 | 11.5–12.5px | 400 |

## 5. 形状、间距与动效

- 圆角：小按钮和侧栏项 7–8px，卡片 12px，审批卡片 14px，对话框 18px，输入框 20px，用户消息气泡 20px，应用图标 22.5%。
- 描边：一律用 0.5px 的 `--hair` / `--hair2`（用 `box-shadow: 0 0 0 .5px` 实现），不用 1px 实线框。
- 阴影：只有浮起的东西才有阴影；普通内容块只用描边。
- 间距：以 4px 为单位；对话流中块与块之间 14px，轮与轮之间 28px。
- 动效：悬停和切换 150ms，曲线 `cubic-bezier(.2,.8,.2,1)`；运行中用小转圈和流光文字；尊重 `prefers-reduced-motion`，关闭所有循环动画。

## 6. 对话页组件

- **用户消息**：右对齐气泡，底色 `--sunk2`，最大宽度 78%；附带的文件以小卡片显示在气泡上方（文件类型图标 + 路径）。
- **思考过程**：一行灰字“思考了 6 秒”，可展开。
- **工具时间线**：每一步一行，左侧是节点（完成为绿色 ✓，进行中为转圈），节点之间有 1px 竖线；文字是“动作 + 对象”（例如“读取 `src/sum.mjs`”），右侧灰字是耗时或结果摘要。正在进行的步骤用流光文字。
- **助手正文**：完整渲染 Markdown（标题、列表、表格、行内代码、代码块）。
- **审批卡片**：浮起的卡片（`--sh-2`）。标题“要运行这条命令吗？”，下面是命令、触发审批的原因，再下面是编号选项：
  1. 运行一次（Enter）
  2. 运行，并且以后同类命令不再询问（写明作用范围：仅此项目）
  3. 不运行，告诉 Agent 换个做法（Esc）
  数字键 1–3 直接选择。
- **检查点分隔线**：每轮结束处一条细线，中间写“第 N 轮前已保存检查点 · 时间”。
- **轮次操作**：复制、撤销本轮；右侧灰字显示模型名和 token 数。
- **输入框**：上方是运行状态条（转圈 + “正在运行 · 已用时间” + “按 Esc 停止”）；下方左边是附件、权限模式，右边是“供应商 · 模型”选择、上下文占用圆环（悬停显示百分比）、发送或停止按钮（近黑圆形）。
  - 输入框内的高亮：文本框下面叠一层排版完全相同的高亮层（`ComposerHighlight`），文本框自己的文字透明，只留光标与选区。消息开头的 `/` 指令用 `--accent-soft` 底色，`@` 引用用 `--accent-soft` 底色加 `--accent` 文字，成对反引号里的代码用 `--sunk2` 底色，网址加下划线。高亮只能用不改变字宽的样式（底色、下划线），不换字体、不加内边距，否则两层会错位。分词规则在 `composer-tokens.ts`，消息渲染共用同一份。
  - `/` 指令面板：贴在输入框上方的浮层，分“指令”和“技能”两组（`composer.command.group.*`），用一个 11px 的灰字小标题隔开，内置指令在前，已启用且未被覆盖的技能在后。每行是等宽的 `/名称`、灰色的参数提示和一句说明。当前不能执行的指令（运行中的 `/compact`、`/undo`，没有可撤销的轮次）文字变淡，说明换成原因，选中后只提示原因、保留草稿。收参数的指令（`/plan`、`/model`、`/settings`）按 Tab 补全时带一个空格，面板收起，接着写参数，Enter 执行；`/技能名` 单独选中时同样先补全成 `/技能名 `，再写任务，发送时技能正文只注入这一轮。
  - `@` 引用候选：和指令面板同样的浮层，Agent 排在文件前面：Agent 用 Lucide `Bot` 图标、名称和灰色说明；文件与文件夹用 Material 图标（`FileTypeIcon` / `FolderTypeIcon`）、名称和灰色的上级目录（过长时从左边截断）。`@Agent名` 表示把对应的工作交给它，发送时换成 id 交给主 Agent 委派；这些名称不算文件引用。↑↓ 选择，Enter 插入 `@路径 `，在文件夹上按 Tab 进入它继续选，Esc 关闭；结果被截断时底部提示继续输入缩小范围。新对话页的输入框也有这个浮层，范围是选中的工作空间；还没选项目时只列 Agent。
  - 从文件树或改动面板把文件行拖到输入框上时，边框变强调色（`--accent` 加一圈淡环），放下等同于选中一个 `@` 候选，插到光标处；外部拖进来的文件与文字不处理。
  - 计划模式没有常驻开关：用 `/plan`（或 `/plan 任务描述` 只让这一条走计划模式）、`Ctrl+Shift+P` 开启；开启时工具栏左侧出现“计划模式 ×”标记，点一下退出。新对话页同样只认 `/plan` 和快捷键。
- **消息里的引用与路径**：用户消息用同一份分词规则标记开头执行的 `/指令`、这一轮用到的 `/技能名`、`@Agent名` 与 `@文件`，一律是 `--accent-soft` 底色，Agent 名前带 `Bot` 图标；网址加下划线，反引号代码用 `--sunk2` 底色。被主进程确认存在的 `@文件` 是按钮，点击在右侧打开并定位到行号；没确认的保持纯文字。助手正文里行内代码中的相对路径（`src/a.ts`、`src/a.ts:12`）确认存在后同样可点，样式为带下划线的行内代码。打开的文件用 `--accent-soft` 标出目标行，并滚到可见处。
- **危险操作确认框**：模糊遮罩 + 对话框；左上角红色图标，标题写清动作（“撤销第 3 轮的改动？”），正文说明后果，列出受影响的文件并标出每个文件会怎样（恢复原内容 / 删除）；两个等宽按钮，取消在左，红色主按钮在右，按钮文字写明数量（“撤销 2 个文件”）。

## 7. 代码区

### 7.1 代码卡片

- 标题栏高 38px，底色 `--code-head`：文件类型图标（VS Code Material Icon Theme，14px）、路径（目录用 `--muted`，文件名用 `--fg` 加粗）、“新文件”标记、增删行数；右侧是“换行”和“复制”按钮，复制后显示“已复制”1.6 秒。没有文件路径的纯语言代码块继续显示语言缩写小方块。
- 正文：行号列宽 46px，右对齐，`--gutter` 色，不可选中，复制时不带行号。
- Agent 要你注意的行：底色 `--line-hl`，左侧 2px 强调色竖线，行号变为强调色。
- 语法高亮按令牌着色：关键字、函数、字符串、数字、注释（斜体）、标点、类型、属性名。

### 7.2 diff 卡片

- 标题栏与代码卡片相同，增删行数后面跟 5 个小方块表示增删比例；右侧是“合并 / 分栏”切换和“撤销此文件”。
- hunk 标题行：`@@ -1,6 +1,6 @@` 加所在函数名，底色 `--hunk-bg`。
- 每行：旧行号、新行号、`+`/`−` 标记、内容。新增行和删除行整行着色，行号槽颜色更深；行内真正改动的词用 `--add-word` / `--del-word` 再加深一层。
- 未改动的连续代码折叠成一行“展开下方 N 行未改动的代码”。
- 分栏视图：左旧右新，中间 0.5px 分隔线；对侧没有对应行时用斜线底纹占位。窗口宽度不足时自动退回合并视图。

### 7.3 终端卡片

- 无论浅色还是深色主题，都使用深色终端令牌（`--term-*`）。
- 标题栏：`$ 命令`、退出码徽标（0 为绿色 ✓，非 0 为红色 ✕）、耗时、复制。
- 输出区最高 220px，超出后内部滚动；底部一行汇总（例如测试的通过、失败、跳过数量，以及 Shell 和工作目录）。

### 7.4 本轮变更

每轮结束、有文件改动时出现：标题“本轮变更”和总增删数，下面每个文件一行（文件类型图标、路径、新文件标记、增删数、比例方块），点击文件名就地展开对应的 diff；点标题行在右侧工作台打开本会话的全部改动。

## 8. 设置页

- 与对话页相同的窗口结构：左侧分类导航（顶部 Cairn 品牌行与“返回对话 Esc”），右侧纸面，内容居中，最大宽度 840px；表单标签列 148px。
- 分类：通用与外观；模型供应商；MCP 服务、技能；权限与审批。
- **模型供应商**：列表每行显示图标、名称、来源标记（官方 / 第三方中转）、接口格式、模型数、默认标记和连接状态。编辑区依次是：接口格式（Anthropic / OpenAI / Gemini 三选一的卡片）、来源（选“官方”自动填写地址和兼容参数）、名称、Base URL、API Key（显示末 4 位和“已保存到系统钥匙串”）、测试连接结果、模型列表（开关、默认、上下文长度、能力）、高级选项（折叠）。
- **MCP 服务**：每个服务显示名称、类型（本机进程 / 远程 HTTP）、启动命令或地址、连接状态、开关和工具列表；失败时在行内说明原因并提供“查看日志”。下方显示可复制的 `mcp.json`，格式兼容 Claude Desktop 和 Cursor，支持导入。
- **技能**：两列卡片，显示名称、说明、作用范围（全局或某个项目）、路径和开关；支持拖入文件夹或 .zip 安装，安装前展示其中的脚本让用户确认。
- **权限与审批**：只读 / 询问 / 自动三种模式卡片；规则列表按匹配顺序排列，每条显示效果（允许 / 询问 / 拒绝）、规则和来源；底部说明哪些操作无论规则如何都会再次询问。
- **通用与外观**：主题、界面语言、默认 Shell、全局指令。

## 9. 图标与品牌

- 产品名 Cairn（石标），见 [ADR-0025](../adr/0025-product-name-cairn.md)。
- 品牌记号：环石 C（开口环 + 缺口里的一颗小石），产品内与应用图标共用。赭红底板 `#C24A28` 配骨白图形 `#FFF8F3`；深色版墨底配赭红图形。
- 源文件和各尺寸导出放在 `apps/desktop/build/icons/`。
- 图标栏顶部是 36px 圆角底板 + 24px 环石；新对话欢迎页使用 64px 图形，空会话与无 preload 回退页也显示品牌图形。16px 时只保留环与小石，不添加内部细节。
- 界面里的功能图标统一用 1.5px 线宽、圆角端点的线性图标，16px 和 14px 两种尺寸。
- **文件与目录实体图标统一使用 VS Code Material Icon Theme**：依赖 `vscode-material-icons`，通过 `apps/desktop/src/renderer/file-icons.tsx` 的 `FileTypeIcon` / `FolderTypeIcon` 渲染。文件树、工作空间/会话分组、文件标签、代码与 diff 卡片标题、改动集、检查点、技能文件列表等所有表示具体文件或目录的位置都必须使用这两个组件，不要在业务组件里另用 Lucide 的 `File` / `Folder` 或自行维护 SVG。
- 目录按名称匹配图标，展开时使用 Material 的 `-open` 变体；没有匹配项时回退到 `file.svg` / `folder.svg`。打开文件夹、在资源管理器中显示、新建文件/文件夹等**操作按钮**仍使用 Lucide 功能图标，不与实体图标混用。
