## 1. 目标

**完成标准**（架构 §26）：两个模型可切换，所有改动可审阅、可撤销。

具体来说，界面按视觉规范完整实现对话页与设置页：

1. 窗口结构：侧栏铺在窗口底色上，对话在纸面上，浅色 / 深色跟随系统或手动切换。
2. 对话页：Markdown 正文、思考过程、工具时间线、审批卡片、代码 / diff / 终端卡片、本轮变更、检查点分隔线、醒目的撤销确认框、悬浮输入框（运行状态、模型切换、上下文圆环）。
3. 设置页：通用与外观、模型供应商（三种接口格式，官方 / 第三方中转）、权限与审批。

### 1.1 不在本轮范围内

- MCP 服务、技能设置页：后端在 M3，届时一起做；侧栏的“活动”“Agents”入口在 M4 之前不显示。
- 按块（hunk）接受 / 撤销：M3。本轮只做整文件撤销。
- 任何金额显示与预算功能：不做（视觉规范 §10）。只显示 token 数。
- 账户与登录：没有。

### 1.2 任务约定

沿用 M0 / M1 的约定：一个子任务一个 PR，合并后再开始下一个；覆盖率四项不低于 90%；界面文案全部走 i18n（ADR-0013），中英文同时补齐。

M2 另加：

- 组件只引用设计令牌（CSS 变量），不写死颜色。
- 每个界面 PR 在描述中附浅色、深色两张截图（Playwright 在容器中截取）。
- 新依赖需通过许可证检查（ADR-0014）。

## 2. 技术选型

| 用途 | 选择 | 说明 |
|---|---|---|
| 样式 | Tailwind CSS 4（`@tailwindcss/vite`） | ADR-0002。令牌写在 `tokens.css`，在 `@theme` 中映射成工具类（如 `bg-paper`、`text-muted`） |
| 基础组件 | shadcn/ui 的做法：把组件源码放进 `src/renderer/ui/`，底层用 Radix UI | 对话框、下拉菜单、开关、提示、折叠等；按需加入，不整包引入 |
| 图标 | lucide-react | 1.5px 线宽、圆角端点，与规范一致；ISC 许可证 |
| 等宽字体 | JetBrains Mono（`@fontsource/jetbrains-mono`，随应用打包） | OFL-1.1，字体文件不是代码依赖，需在许可证检查中加例外并写进 THIRD_PARTY_NOTICES |
| Markdown | react-markdown + remark-gfm | 不开启原始 HTML，链接用系统浏览器打开 |
| 语法高亮 | Shiki（细粒度包，按需加载语言），主题用规范里的 `--tk-*` 令牌（CSS 变量主题） | 在渲染进程中按需加载，不阻塞首屏 |
| diff | `diff`（jsdiff）计算行级与词级差异 | 主进程已有改动记录（`changes.list`） |
| ANSI | 终端卡片解析颜色（`anser` 或自写小解析器），交给模型前去掉控制符 | 后者在宿主侧做，修复 M1 遗留问题 |

窗口：Windows 用 `titleBarStyle: 'hidden'` + `titleBarOverlay`（系统按钮颜色跟随主题），macOS 用 `hiddenInset`，侧栏顶部留出拖拽区。

## 4. 任务详情

### M2-01 样式基础

- **交付物**
  - Tailwind 4 接入 electron-vite 的 renderer；`tokens.css` 按视觉规范 §3 写全部令牌（浅色 `:root`，深色 `[data-theme="dark"]`，跟随系统时用 `prefers-color-scheme`）。
  - 主题：设置新增 `theme: 'system' | 'light' | 'dark'`，界面启动时应用（Windows 标题栏按钮颜色随 M2-02 的无边框窗口同步）。
  - 字体：界面字体栈；JetBrains Mono 打包，关闭连字，数字等宽。
  - 基础组件：Button（主 / 次 / 幽灵 / 危险）、IconButton、Dialog、DropdownMenu、Tooltip、Switch、SegmentedControl、Kbd、Spinner、流光文字；尊重 `prefers-reduced-motion`。
  - 一个只在开发模式打开的组件预览页，方便对照参考稿。
- **验收**：组件单测；浅色 / 深色截图；许可证检查通过；现有测试不受影响。
- **实施记录**
  - M2-01：
    - 依赖：`tailwindcss`、`@tailwindcss/vite` 4.3.4（开发依赖），`radix-ui` 1.8.1、`lucide-react` 1.70.0、`clsx`、`tailwind-merge`、`class-variance-authority`、`@fontsource/jetbrains-mono` 5.3.0。字体为 OFL-1.1，登记在 `scripts/license-exceptions.json`；只引入 latin 子集的 400、600 两种字重。
    - 令牌：`styles/tokens.css` 由视觉规范 §3 的表格生成（浅色 `:root`，深色 `[data-theme='dark']`）；`styles/index.css` 在 `@theme inline` 中映射为工具类（`bg-paper`、`text-muted`、`shadow-2`、`rounded-card`、`text-body` 等），并去掉 Tailwind 自带调色板，组件只能用令牌颜色。代码、路径关闭连字，`tabular` 工具类为等宽数字；减少动态效果时关闭动画与过渡。
    - 主题：protocol `Theme` 与 `Settings.theme`（可选，没有时按跟随系统）；`theme.ts` 把主题解析为浅色或深色写到 `<html data-theme>`，跟随系统时监听 `prefers-color-scheme`；`ThemeSync` 启动时读取设置并跟随设置变化。入口在设置读到之前先按系统主题应用，避免闪白。
    - 基础组件（`src/renderer/ui/`）：Button（主 / 次 / 幽灵 / 危险）、IconButton、Dialog（模糊遮罩，危险样式的图标）、DropdownMenu、Tooltip、Switch、SegmentedControl（单选组，方向键切换）、Kbd、Spinner、Shimmer；`cn` 让 tailwind-merge 认识自定义字号与阴影。
    - 组件预览页：开发模式下地址带 `#preview` 时显示（`dev/ComponentPreview.tsx`），只用于对照参考稿与截图，i18n lint 对 `dev/` 豁免。
    - 现有 M1 界面未改动，只是全局有了基础样式；迁入新布局在 M2-02。

### M2-05 工具时间线与审批卡片

- **交付物**
  - 工具调用改成时间线：节点（完成 ✓、进行中转圈、失败 ✕）、竖线、“动作 + 对象”文字、右侧耗时或结果摘要、进行中流光文字；点击展开详情（输出、参数）。工具在思考过程之后、正文之前按实际顺序显示（修复 M1 层级不清的问题）。
  - 审批卡片：标题、命令或路径、触发原因、三个编号选项（运行一次 Enter / 以后同类不再询问（写明作用范围）/ 不运行并告诉 Agent 换做法 Esc），数字键 1–3 直接选择。
- **验收**：键盘操作单测；现有 e2e 全部通过。
- **实施记录**
  - M2-05：
    - 工具时间线（`ToolTimeline.tsx`，替换 `ToolCallCard.tsx`）：每步一行，节点（完成 ✓、进行中转圈、失败 ✕、等待中空心圆、取消 –）由竖线连起来；文字是“动作 + 对象”（读取 / 写入 / 编辑 / 查看目录 / 搜索 / 运行 + 路径、搜索词或命令，其他工具显示工具名 + 参数摘要）；右侧是耗时（完成）或状态，等待审批的步骤显示“等待审批”；进行中的步骤文字流光。点击一行展开参数与完整输出（可滚动）、截断说明；失败的错误不用展开就显示；执行中显示实时输出的最后几行（M2-06 换终端卡片）。
    - 顺序：思考过程 → 正文 → 这条消息的工具时间线。模型在同一条消息里先写正文再调用工具，所以“按实际顺序”就是正文在前；最终回复是下一条消息，自然在工具之后。同一轮中紧跟的助手消息间距收紧为块间距（14px），轮与轮之间仍是 28px。
    - 审批卡片：浮起的卡片，标题是问题（要运行这条命令吗？ / 要修改这些文件吗？ / 要执行这个操作吗？ / 无法创建检查点，仍要继续吗？），右上角灰字工具名；下面是命令（`$` 前缀）、diff、路径或参数，以及原因；三个编号选项：1 运行（允许）一次（Enter）、2 以后同类不再询问（仅此项目，即 `allow_project`）、3 不运行，告诉 Agent 换个做法（Esc）。选 3 出现说明输入框，Enter 提交（说明交给模型）。“本会话始终允许”不再出现在界面上（协议保留）。没有检查点时只有 1 和 3。
    - 键盘：数字键 1–3 直接选择，Enter 选 1，Esc 拒绝。只有最早的一张卡片响应；在有内容的输入框里打字、按着 Ctrl / ⌘ / Alt、或有对话框和菜单打开时不响应（发送后焦点仍在空输入框里也能直接按）。输入框的“Esc 停止”在等待审批时不生效，不会冲突。
    - 对话列贴底滚动（`stick-to-bottom.ts`）：停在底部附近时，内容变高（新消息、流式输出、展开工具步骤、审批卡片出现）就跟着滚到底，审批卡片完整停在输入框上方；往上翻看时不打扰；切换会话回到底部。内容不满一屏时从顶部排起（和常见对话应用一致）。对话列底部留白加到 32px，卡片阴影不被裁掉。
    - e2e：审批用新的选项名；完整流程中运行命令的审批用数字键 1 完成；消息列表只取直接子项（时间线是嵌套列表）。

### M2-06 代码卡片与终端卡片

- **交付物**
  - 代码卡片（规范 §7.1）：标题栏（语言图标、路径、新文件标记、增删数、换行、复制→“已复制”）、行号、重点行、Shiki 高亮；Markdown 代码块与 `read_file` 结果都用它。
  - 终端卡片（规范 §7.3）：`$ 命令`、退出码徽标、耗时、复制；输出区最高 220px 内部滚动；ANSI 颜色按终端令牌渲染；底部汇总（Shell、工作目录，能识别时显示测试通过 / 失败数）。
  - 宿主：`run_command` 交给模型的输出去掉 ANSI 控制符（并设置 `NO_COLOR=1`），界面仍拿到原始输出用于着色。
- **验收**：ANSI 解析与去除单测；长输出性能（1 万行不卡顿）。
- **实施记录**
  - M2-06：
    - ANSI（`@cairn/core` 的 `ansi.ts`）：`stripAnsi` 与流式的 `AnsiStripper`（控制序列跨块时暂存，最多 8 KiB）去掉 CSI / OSC / 其他 ESC 序列；`\r` 覆盖同一行时只保留最后一段非空内容，`\r\n` 当换行。`AnsiParser` / `parseAnsi` 把输出解析为按行的带样式片段：SGR 支持 16 色、256 色（转成最接近的 16 色下标）、真彩色、粗体、暗淡、斜体、下划线、反显、删除线，片段标记来自标准输出还是标准错误。1 万行解析在单测中限时 200ms。
    - 宿主：`run_command` 交给模型的标准输出 / 标准错误先去掉控制符再按原来的首尾截断；子进程环境固定 `NO_COLOR=1`（和 `PYTHONUTF8=1` 一样不能被覆盖）。原始输出（保留 ANSI）按输出流分段，最多 64 KiB（与实时输出上限相同），超出时保留开头与结尾、在中间记下省略的字符数，结尾从完整的一行开始。
    - 协议：`tool.completed` 新增可选的 `display`（只给界面，不进模型历史）：`{ kind: 'terminal', exitCode, signal?, timedOut, aborted, durationMs, shell, cwd, chunks, omittedChars, omittedAt? }`。字段可选，事件版本不变；`SessionView` 的工具调用带上 `display`。M2-06 之前的事件没有 `display`，界面从交给模型的文本解析出退出码、耗时与输出（没有颜色、Shell 与工作目录）。
    - 高亮：Shiki 4.6.0 的细粒度包（`@shikijs/core`、`@shikijs/engine-javascript`、`@shikijs/langs`，MIT），JavaScript 正则引擎，不打包 WASM；语言按需加载（`languages.ts`，22 种，含常见别名与扩展名），不认识的语言按纯文本显示。主题是自定义的 `cairnTheme`，颜色直接写 `var(--tk-*)`，切换浅色 / 深色不用重新高亮；结果按代码与语言缓存 64 条，超过 20 万字符不高亮。
    - 代码卡片（`CodeCard.tsx`）：38px 标题栏（语言图标、目录灰字 + 文件名、新文件标记、+N / −N、换行开关、复制→“已复制”1.6 秒）；46px 行号列不可选中、不给读屏（行号超过 4 位时加宽）；重点行用 `--line-hl` 底色和左侧强调线。Markdown 代码块用它，info string 后的花括号写重点行（` ```ts {2,4-6} `）；`read_file` 的结果展开后用它，行号从读取的起始行开始，分段读取等说明显示在卡片下方。
    - 终端卡片（`TerminalCard.tsx`）：标题栏 `$ 命令`、退出码徽标（0 绿色 ✓，非 0 红色 ✕；超时、取消、信号分别说明；运行中转圈）、耗时、复制（复制去掉控制符的输出）；输出区最高 220px，按 21px 固定行高只渲染看得见的行（前后各多 20 行），1 万行不卡顿；运行中停在底部时跟随新输出。ANSI 16 色对应新的终端调色板令牌 `--term-c0` ～ `--term-c15`，标准错误中没有颜色的文字用 `--term-err`。底部汇总显示能识别的测试数（vitest / jest / pytest / cargo）与“Shell · 工作目录”。
    - 时间线：`run_command` 执行中直接显示终端卡片（替换实时输出预览），完成后退出码非 0 时默认展开，其余默认收起；`read_file` 展开显示代码卡片；其他工具不变。
    - 令牌：视觉规范 §3 新增终端调色板（`--term-c0` ～ `--term-c15`、`--term-err`，两种主题相同，终端底色始终是深色）。

### M2-07 diff 与本轮变更

- **交付物**
  - diff 卡片（规范 §7.2）：hunk 标题、旧 / 新行号、整行与词级着色、折叠未改动的行、合并 / 分栏切换（窄窗自动合并）、增删比例方块、“撤销此文件”。
  - 本轮变更（规范 §7.4）：每轮有改动时出现，点击文件打开对应 diff。
  - 顶栏改动摘要“N 个文件 +a −b”，点击展开本会话所有改动。
- **后端**：读取某次改动的前后内容（blob），撤销单个文件（复用改动记录 / 检查点恢复，单文件范围）。
- **实施记录**
  - M2-07：
    - 协议：`changes.content`（参数 `sessionId`、`changeId`，结果 `before?`、`after?`）。`FileContent` 三种：`text`（最多 100 万字符）、`binary`、`too_large`（后两种只给字节数）。会话不存在、改动不存在或不属于该会话报 `changes.not_found`；内容 blob 缺失报 `changes.content_missing`（与撤销时的 `changes.blob_missing` 分开，文案不说“无法撤销”）。
    - 宿主：`toFileContent` 按读取文件的规则解码（BOM、UTF-16；含 NUL 视为二进制）。新建没有 `before`，删除没有 `after`。
    - 依赖：界面用 `diff` 9.0.0（jsdiff）做行对齐与词级比较。
    - diff 模型（`diff-model.ts`）：先去掉相同的首尾，再 `diffArrays`，上下文 3 行；超过 500ms 退回“整段删除再整段新增”。同一处删除行与新增行按顺序配对，`diffWordsWithSpace` 标出词级改动；两行合计超过 1000 字符，或相同部分不足 40%，只整行着色。只隔着空白的词级改动合成一段。hunk 函数名沿用 git 默认规则：hunk 之前最近一行以字母、`_` 或 `$` 开头的旧文本，最长 80 字符。
    - diff 卡片（`DiffCard.tsx`）：hunk 标题（`@@ … @@` 与函数名）、旧 / 新行号、整行与词级着色；未改动的行折叠成“展开下方 N 行未改动的代码”；一次最多显示 1000 行，其余点“显示其余 N 行”。合并 / 分栏切换，窄于 640px 只用合并视图。5 个增删比例方块。二进制与过大不显示增删数，只说明原因；前后相同显示“内容没有变化”，新建的空文件显示“空文件”。
    - 本轮变更（`TurnChanges`）：每轮有改动时出现在该轮操作上方。按文件合并仍然有效的改动（已撤销的与撤销产生的反向记录不算；新建后又删除的不显示）。点一行展开 diff，内容取这个文件最早一次改动之前与最后一次改动之后。列表上的增删数是各次改动之和，展开后卡片上的数字以实际 diff 为准。
    - 顶栏摘要（`SessionChanges`）：“N 个文件 +a −b”，点开对话框列出本会话所有改动的文件，同样可以展开 diff、撤销单个文件。
    - 撤销此文件：确认框写明结果（修改与删除是恢复原内容，新建是删除文件），确认后复用 `changes.revert`，一次撤销这个文件的全部有效改动。会话正在运行，或还没有会话投影时，按钮不可用。收到 `file.changed` 后重新读取 `changes.list`。
    - 撤销本轮（恢复检查点）后：本会话在该检查点之后记录的有效改动标记为 `reverted`，界面收到 `checkpoint.restored` 后重新读取 `changes.list`，本轮变更与顶栏摘要不再列出已经恢复的文件。撤销这次恢复时的处理见 M2-08。

### M2-08 检查点与撤销确认

- **交付物**：每轮结束处检查点分隔线“第 N 轮前已保存检查点 · 时间”；撤销确认框按规范 §6 重做：模糊遮罩、红色图标、标题写清动作、列出受影响文件及各自结果（恢复 / 删除）、等宽两按钮且写明数量；左侧对话导航条（合并检查点入口，替代原计划的顶栏菜单）可回退到任一轮。
- **验收**：修复 M1 遗留的“撤销确认框不醒目”；e2e 撤销流程更新。
- **实施记录**
  - M2-08：
    - 会话投影（`@cairn/core`）：`SessionView` 新增 `checkpoints`（`checkpoint.created`：id、原因、seq、轮次、时间）与 `restores`（`checkpoint.restored`），界面不再为撤销本轮单独请求 `checkpoint.list`（store 去掉 `turnCheckpoint`）。
    - 改动状态随恢复同步（主进程 `checkpoint-service`）：恢复后按事件重放到目标检查点为止，得出每条改动那时是否有效：`file.changed` 记下改动（撤销产生的反向记录把原改动记为已撤销），`checkpoint.restored` 把它的恢复点之后、它之前的改动记为已撤销；目标检查点之后的改动都记为已撤销。与现状不同的改为 `reverted` 或改回 `pending`，反向记录本身不变。因此撤销这次恢复（恢复到 `before_restore`）后，被这次恢复撤销的改动重新出现在本轮变更与顶栏摘要中。
    - 检查点分隔线（`Checkpoints.tsx`）：每轮第一条用户消息上方一条细线“第 N 轮前已保存检查点 · 时:分”（不是今天时加日期），`role="separator"`。放在用户消息的列表项里，消息列表的直接子项仍然只有消息。
    - 撤销确认框按规范 §6 重做（`RestoreDialog`，替换 `UndoTurn.tsx`）：模糊遮罩、红色图标；标题“撤销第 N 轮的改动？”，不是最后一轮时“撤销第 N 轮及之后的改动？”，撤销恢复时“撤销这次恢复？”；正文说明对话记录保留、之后还能撤销；打开时预览，列出受影响的文件和结果（恢复原内容 / 恢复 / 删除，删除用红字），按修改、恢复、删除排序；等宽两按钮，主按钮“撤销 N 个文件”，没有需要恢复的文件时不可用。成功后关闭，结果由恢复标记显示。
    - 入口：轮次操作中复制旁边是“撤销本轮”图标按钮（这一轮有 `turn_start` 检查点时）。原计划的顶栏“历史与检查点”菜单按 lan 的意见（右上角不习惯）改为对话列左侧的**对话导航条**（`TurnRail`，两轮及以上时显示）：每轮一条短横线（改动过文件的轮次颜色更深），点击跳到这一轮；悬停或聚焦时显示预览卡片（第几轮、改动了几个文件、用户消息与回复的开头、检查点时间），卡片上“回到这一轮之前”打开同一个确认框。撤销某次恢复只从恢复标记进入。会话正在运行、等待审批或已发送等待开始时，这些入口不可用。
    - 恢复标记：恢复后，在当时最后一条消息下方显示“已撤销到第 N 轮开始之前 · 时间”（撤销恢复时“已撤销上一次恢复”）；最近一次恢复旁边是“撤销这次恢复”按钮（恢复到恢复前自动保存的检查点）。
    - e2e：撤销本轮的两个用例改用新的确认框；撤销本轮之后再撤销这次恢复，新建的文件回来。
