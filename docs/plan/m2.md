## 1. 目标

**完成标准**（架构 §26）：两个模型可切换，所有改动可审阅、可撤销。

具体来说，界面按视觉规范完整实现对话页与设置页：

1. 窗口结构：侧栏铺在窗口底色上，对话在纸面上，浅色 / 深色跟随系统或手动切换。
2. 对话页：Markdown 正文、思考过程、工具时间线、审批卡片、代码 / diff / 终端卡片、本轮变更、检查点分隔线、醒目的撤销确认框、悬浮输入框（运行状态、模型切换、上下文圆环）。
3. 设置页：通用与外观、模型供应商（三种接口格式，官方 / 第三方中转）、权限与审批。

### 1.1 不在本轮范围内

- MCP 服务、技能设置页：后端在 M3，届时一起做；侧栏的“活动”“Agents”入口在 M4 之前不显示。
- 按块（hunk）接受 / 撤销：M3。本轮只做整文件撤销。
- 任何金额显示与预算功能：不做（视觉规范 §10）。只显示 token 数。
- 账户与登录：没有。

### 1.2 任务约定

沿用 M0 / M1 的约定：一个子任务一个 PR，合并后再开始下一个；覆盖率四项不低于 90%；界面文案全部走 i18n（ADR-0013），中英文同时补齐。

M2 另加：

- 组件只引用设计令牌（CSS 变量），不写死颜色。
- 每个界面 PR 在描述中附浅色、深色两张截图（Playwright 在容器中截取）。
- 新依赖需通过许可证检查（ADR-0014）。

## 2. 技术选型

| 用途 | 选择 | 说明 |
|---|---|---|
| 样式 | Tailwind CSS 4（`@tailwindcss/vite`） | ADR-0002。令牌写在 `tokens.css`，在 `@theme` 中映射成工具类（如 `bg-paper`、`text-muted`） |
| 基础组件 | shadcn/ui 的做法：把组件源码放进 `src/renderer/ui/`，底层用 Radix UI | 对话框、下拉菜单、开关、提示、折叠等；按需加入，不整包引入 |
| 图标 | lucide-react | 1.5px 线宽、圆角端点，与规范一致；ISC 许可证 |
| 等宽字体 | JetBrains Mono（`@fontsource/jetbrains-mono`，随应用打包） | OFL-1.1，字体文件不是代码依赖，需在许可证检查中加例外并写进 THIRD_PARTY_NOTICES |
| Markdown | react-markdown + remark-gfm | 不开启原始 HTML，链接用系统浏览器打开 |
| 语法高亮 | Shiki（细粒度包，按需加载语言），主题用规范里的 `--tk-*` 令牌（CSS 变量主题） | 在渲染进程中按需加载，不阻塞首屏 |
| diff | `diff`（jsdiff）计算行级与词级差异 | 主进程已有改动记录（`changes.list`） |
| ANSI | 终端卡片解析颜色（`anser` 或自写小解析器），交给模型前去掉控制符 | 后者在宿主侧做，修复 M1 遗留问题 |

窗口：Windows 用 `titleBarStyle: 'hidden'` + `titleBarOverlay`（系统按钮颜色跟随主题），macOS 用 `hiddenInset`，侧栏顶部留出拖拽区。

## 4. 任务详情

### M2-01 样式基础

- **交付物**
  - Tailwind 4 接入 electron-vite 的 renderer；`tokens.css` 按视觉规范 §3 写全部令牌（浅色 `:root`，深色 `[data-theme="dark"]`，跟随系统时用 `prefers-color-scheme`）。
  - 主题：设置新增 `theme: 'system' | 'light' | 'dark'`，界面启动时应用（Windows 标题栏按钮颜色随 M2-02 的无边框窗口同步）。
  - 字体：界面字体栈；JetBrains Mono 打包，关闭连字，数字等宽。
  - 基础组件：Button（主 / 次 / 幽灵 / 危险）、IconButton、Dialog、DropdownMenu、Tooltip、Switch、SegmentedControl、Kbd、Spinner、流光文字；尊重 `prefers-reduced-motion`。
  - 一个只在开发模式打开的组件预览页，方便对照参考稿。
- **验收**：组件单测；浅色 / 深色截图；许可证检查通过；现有测试不受影响。
- **实施记录**
  - M2-01：
    - 依赖：`tailwindcss`、`@tailwindcss/vite` 4.3.4（开发依赖），`radix-ui` 1.8.1、`lucide-react` 1.70.0、`clsx`、`tailwind-merge`、`class-variance-authority`、`@fontsource/jetbrains-mono` 5.3.0。字体为 OFL-1.1，登记在 `scripts/license-exceptions.json`；只引入 latin 子集的 400、600 两种字重。
    - 令牌：`styles/tokens.css` 由视觉规范 §3 的表格生成（浅色 `:root`，深色 `[data-theme='dark']`）；`styles/index.css` 在 `@theme inline` 中映射为工具类（`bg-paper`、`text-muted`、`shadow-2`、`rounded-card`、`text-body` 等），并去掉 Tailwind 自带调色板，组件只能用令牌颜色。代码、路径关闭连字，`tabular` 工具类为等宽数字；减少动态效果时关闭动画与过渡。
    - 主题：protocol `Theme` 与 `Settings.theme`（可选，没有时按跟随系统）；`theme.ts` 把主题解析为浅色或深色写到 `<html data-theme>`，跟随系统时监听 `prefers-color-scheme`；`ThemeSync` 启动时读取设置并跟随设置变化。入口在设置读到之前先按系统主题应用，避免闪白。
    - 基础组件（`src/renderer/ui/`）：Button（主 / 次 / 幽灵 / 危险）、IconButton、Dialog（模糊遮罩，危险样式的图标）、DropdownMenu、Tooltip、Switch、SegmentedControl（单选组，方向键切换）、Kbd、Spinner、Shimmer；`cn` 让 tailwind-merge 认识自定义字号与阴影。
    - 组件预览页：开发模式下地址带 `#preview` 时显示（`dev/ComponentPreview.tsx`），只用于对照参考稿与截图，i18n lint 对 `dev/` 豁免。
    - 现有 M1 界面未改动，只是全局有了基础样式；迁入新布局在 M2-02。

### M2-02 窗口与侧栏

- **交付物**
  - 无边框窗口与拖拽区；侧栏 252px：新对话（Ctrl+N）、搜索（Ctrl+K，先占位）、按项目分组的会话列表（运行中显示转圈，可重命名、删除）、底部模型供应商卡片（已配置的供应商与默认模型，点击进入设置）。
  - 纸面与顶栏：面包屑“项目 / 会话标题”，右侧预留改动摘要与更多菜单。
  - 窗口宽度小于 880px 时侧栏收起，可手动展开。
  - 现有 M1 界面（SessionList、ChatPanel 等）迁入新布局；模型设置对话框暂时保留，M2-10 后删除。
- **后端**：`session.rename`、`session.archive`（事件已存在，补 RPC）。
- **实施记录**
  - M2-02：
    - 窗口：`main/window-chrome.ts`。macOS 用 `hiddenInset`（红绿灯在侧栏左上角），Windows / Linux 用 `hidden` + `titleBarOverlay`（高 40px，颜色取 `--chrome` / `--fg2`）；窗口底色随主题，最小 640×480。主进程把 `nativeTheme.themeSource` 设为设置中的主题，主题变化时更新系统按钮颜色。侧栏顶部与纸面顶栏可拖动窗口（`drag` / `no-drag` 工具类），顶栏右侧按 `env(titlebar-area-*)` 给系统按钮让出位置。
    - 侧栏（`layout/Sidebar.tsx`）：收起按钮、新对话（⌘N / Ctrl+N）、按项目分组的会话列表、底部模型供应商卡片（供应商数与默认模型，点击打开原有的“模型设置”，改为对话框）与界面语言。搜索、活动、Agents 入口未加入（M2-12 / M4）。
    - 会话列表：运行中转圈，等待审批与失败 / 崩溃用彩色圆点并有读屏文字；悬停出现“会话操作”菜单：重命名（就地编辑，Enter 保存、Esc 取消，未改动不保存）与删除（危险确认框，确认后归档）。
    - 纸面：顶栏“项目 / 会话标题”（标题仍是二级标题，e2e 不变）；对话列最大宽度 700px，输入框在底部；错误横幅浮在顶栏下方。新对话表单从侧栏移到纸面（`NewSession.tsx`），还没有会话时直接显示。
    - 窗口宽度小于 880px 时侧栏收起，可以从顶栏展开。
    - 后端：protocol `session.rename`（标题最多 200 个字符，去掉首尾空白）、`session.archive`（运行中报 `run.busy`）；会话管理器写入 `session.renamed` / `session.archived`；store 新增 `renameSession`、`archiveSession`（归档当前会话时取消选中）。
    - `Spinner` 不再使用 `role="status"`（页面上只有 ChatPanel 的运行状态一个 status 区域）。
    - e2e：按钮“新建会话”改为“新对话”；模型设置对话框用“关闭”按钮关闭。

### M2-03 对话消息

- **交付物**：用户消息气泡（附件小卡片位置预留）；助手正文完整渲染 Markdown（标题、列表、表格、行内代码、代码块先用简易样式，M2-06 换成代码卡片）；思考过程一行“思考了 N 秒”，可展开；轮次操作：复制、撤销本轮（入口），右侧灰字模型名与 token 数；中断的回复标出“未完成”。
- **验收**：Markdown 渲染与 XSS 防护（原始 HTML 不渲染）单测；修复 M1 遗留的“Markdown 原样显示”。
- **实施记录**
  - M2-03：
    - 用户消息：右对齐气泡（最宽 78%），原样显示并保留换行，不按 Markdown 解释。作者名（“你” / “助手”）只给读屏。
    - 助手正文：`Markdown.tsx`（react-markdown + remark-gfm）。标题降为 h3/h4，列表、表格、引用、行内代码与代码块按视觉规范 §6 的简易样式；不渲染原始 HTML，`javascript:` 等链接由默认 urlTransform 去掉，链接在系统浏览器打开。进行中的回复同样按 Markdown 渲染。
    - 思考过程：可展开的“思考过程”，正在思考时文字流光。事件中没有思考时长，先不显示“思考了 N 秒”（M2-12 视情况补）。
    - 轮次操作：本轮结束后，在最后一条助手消息下显示复制按钮（复制本轮所有助手回复的文本）与灰字“供应商 · 模型 · N tokens”（输入 + 输出，不显示金额）。撤销本轮的入口留给 M2-08（检查点分隔线与撤销确认框）。
    - core：`SessionView.usageByTurn` 按 turnId 累计 `usage.reported`。
    - 冒烟测试修复（随 #88 合入）：无头模式不用 titleBarOverlay；界面加读屏用的应用名标题。

### M2-04 输入框

- **交付物**：悬浮输入框（自动增高，Enter 发送、Shift+Enter 换行）；上方运行状态条（转圈、已用时间、“按 Esc 停止”）；下方：权限模式（只读 / 询问 / 自动）、“供应商 · 模型”切换（下拉列出已配置模型，切换后下一轮生效）、上下文占用圆环（悬停显示百分比和 token 数）、发送 / 停止按钮；底部提示“修改文件前会自动保存检查点”。
- **验收**：交互单测；在 e2e 中切换两个模型各跑一轮（M2 完成标准之一）。

### M2-05 工具时间线与审批卡片

- **交付物**
  - 工具调用改成时间线：节点（完成 ✓、进行中转圈、失败 ✕）、竖线、“动作 + 对象”文字、右侧耗时或结果摘要、进行中流光文字；点击展开详情（输出、参数）。工具在思考过程之后、正文之前按实际顺序显示（修复 M1 层级不清的问题）。
  - 审批卡片：标题、命令或路径、触发原因、三个编号选项（运行一次 Enter / 以后同类不再询问（写明作用范围）/ 不运行并告诉 Agent 换做法 Esc），数字键 1–3 直接选择。
- **验收**：键盘操作单测；现有 e2e 全部通过。

### M2-06 代码卡片与终端卡片

- **交付物**
  - 代码卡片（规范 §7.1）：标题栏（语言图标、路径、新文件标记、增删数、换行、复制→“已复制”）、行号、重点行、Shiki 高亮；Markdown 代码块与 `read_file` 结果都用它。
  - 终端卡片（规范 §7.3）：`$ 命令`、退出码徽标、耗时、复制；输出区最高 220px 内部滚动；ANSI 颜色按终端令牌渲染；底部汇总（Shell、工作目录，能识别时显示测试通过 / 失败数）。
  - 宿主：`run_command` 交给模型的输出去掉 ANSI 控制符（并设置 `NO_COLOR=1`），界面仍拿到原始输出用于着色。
- **验收**：ANSI 解析与去除单测；长输出性能（1 万行不卡顿）。

### M2-07 diff 与本轮变更

- **交付物**
  - diff 卡片（规范 §7.2）：hunk 标题、旧 / 新行号、整行与词级着色、折叠未改动的行、合并 / 分栏切换（窄窗自动合并）、增删比例方块、“撤销此文件”。
  - 本轮变更（规范 §7.4）：每轮有改动时出现，点击文件打开对应 diff。
  - 顶栏改动摘要“N 个文件 +a −b”，点击展开本会话所有改动。
- **后端**：读取某次改动的前后内容（blob），撤销单个文件（复用改动记录 / 检查点恢复，单文件范围）。

### M2-08 检查点与撤销确认

- **交付物**：每轮结束处检查点分隔线“第 N 轮前已保存检查点 · 时间”；撤销确认框按规范 §6 重做：模糊遮罩、红色图标、标题写清动作、列出受影响文件及各自结果（恢复 / 删除）、等宽两按钮且写明数量；顶栏“历史与检查点”菜单列出本会话检查点，可回退到任一轮。
- **验收**：修复 M1 遗留的“撤销确认框不醒目”；e2e 撤销流程更新。

### M2-09 设置页框架与通用

- **交付物**：设置页与对话页同结构（左侧分类，顶部“返回对话 Esc”，右侧纸面居中 760px）；“通用与外观”：主题、界面语言、默认 Shell、全局指令（`Settings.instructions`，已有后端）。语言切换从顶部移到这里。

### M2-10 模型供应商

- **交付物**（规范 §8）：供应商列表（图标、名称、官方 / 第三方中转、接口格式、模型数、默认、连接状态）；编辑区：接口格式三选一卡片、来源（选官方自动填地址和兼容参数，如 DeepSeek）、名称、Base URL、API Key（显示末 4 位与“已保存到系统钥匙串”）、测试连接、模型列表（开关、默认、上下文长度、能力）、高级选项（折叠）。手动添加模型。删除 M1 的模型设置对话框。
- **后端**：`provider.test`（发一次最小请求，返回延迟或错误原因）、`provider.models`（拉取模型列表，失败时允许手填）。这两项也是架构里 M2 的“能力探测”的起点。
- **不做**：单价字段与任何金额。

### M2-11 权限与审批

- **交付物**：只读 / 询问 / 自动三种模式卡片；规则列表（按匹配顺序，效果、规则、来源，可增删和调整顺序）；底部说明哪些操作始终会再次询问。
- **后端**：读写项目与全局权限规则的 RPC（权限引擎已有，M1-10）。

### M2-12 收尾与验收

- **交付物**：快捷键（Ctrl+N、Ctrl+K 搜索会话、Esc、Ctrl+,）；空状态（没有供应商时引导去设置，没有项目时引导选择文件夹）；错误横幅样式；e2e 全流程更新（两个模型切换、审阅 diff、撤销单个文件、撤销本轮）。
- **[用户本地]**：在 Windows 上用真实模型走一遍，确认观感与参考稿一致。
