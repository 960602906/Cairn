# Cairn 里程碑 8：PR 自动修复

> 状态：**M8-01～M8-05 实施完成**（2026-11-18，随 0.1.2 beta 发布）。M0～M7 已完成。
> 上级文档：[架构设计](../architecture.md) §26；前一阶段：[M7 验收报告](m7-report.md)。
> 设计细节与完整流程：[自动修复设计](auto-fix.md)。
> 相关决策：ADR-0018（交互与无人值守运行）、ADR-0031（隔离工作区）、ADR-0032（活动中心）、
> ADR-0045（自动修复的推送边界）。

## 1. 目标

**完成标准**：

1. 会话里可以为一个 PR 建立监视；CI 失败、合并冲突或出现新的评审意见时，自动触发一次
   无人值守修复。
2. 修复在独立 worktree 中完成，不改动用户当前工作目录；提交与推送只作用于该 PR 的 head 分支。
3. 硬边界：不合并、不改保护分支、不推送其他分支，也不允许 `--force` / `--force-with-lease`；
   检查通过或尝试次数用尽后停止并通知。
4. 过程可见：自动修复会话在会话列表、活动中心与后台任务面板中可见，可以随时停止。
5. 单元、集成与端到端用例覆盖主要链路，三平台 CI 与覆盖率门槛保持通过。

### 1.1 不在本轮范围

- **其他托管平台**：只实现 GitHub REST；GitLab、Bitbucket 等留给后续。
- **Webhook 与常驻服务**：桌面应用没有稳定公网入口，采用本地轮询。
- **自动合并与改写历史**：不自动合并 PR，不改保护分支，不使用 force / force-with-lease。
- **回复评审意见**：`pr_comment` 只在设计里保留，未接入实际工具。
- **多账号与自建实例**：不做账号切换与组织级配置；GitHub Enterprise / 自建实例没有正式支持。
  测试用的 `CAIRN_GITHUB_API_URL` 只接受 HTTPS 或回环 HTTP，避免把令牌发到别处。

## 3. 后续调整

- **0.1.4 起不再有设置页入口**：移除设置页「自动修复」分类与 `github.*` 渲染进程接口。令牌按
  `GH_TOKEN` / `GITHUB_TOKEN` → 旧版保存的凭据 → `gh auth token` 静默解析；PR 监视改由会话里的
  `watch_pull_request` 开启（调用仍走审批），活动中心可以逐条停止。
- **0.1.5 起纳入后台任务面板**：会话工作台的「后台」面板与工作台首页概览会列出自动修复任务。
- **权限边界**：`git_commit` / `git_push` 只在自动修复会话里放行；普通会话只注册
  `watch_pull_request`，由宿主转发给主进程。

真实的 GitHub 推送与回检不在 e2e 中执行：假 GitHub 无法接收真实推送，这部分由
`auto-fix-service.test.ts` 在本地裸仓库上覆盖。自动修复的 e2e 用 `CAIRN_GITHUB_API_URL`
指向本机回环地址，只在开发构建里生效。

## 5. 已知缺口与未执行项

- **`pr_comment` 未接入**：设计里保留“在 PR 上回复评审意见”的可选工具，当前只读取评论并触发
  修复，不自动回复。
- **真实远端验证有限**：推送、回检与冲突合并由单元测试在本地裸仓库上覆盖，没有对真实 GitHub
  仓库做端到端演练。
- **托管平台与账号范围**：只支持 GitHub 单账号；GitHub Enterprise / 自建实例、多账号与组织级
  配置没有产品化。
- **不做自动合并与历史改写**：这是硬边界，不是缺口；需要时由用户在界面上显式操作。
- **stable 发布的前置条件**仍按 M6 报告 §7 延期，与本轮无关。
