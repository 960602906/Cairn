# M1 最小可用：任务概要

> 状态：概要。M0 完成、预研结论落定后再细化为与 [M0](m0.md) 同样粒度的任务。
> 上级文档：[架构设计](../architecture.md) 第 26 节。

## 1. 目标

**完成标准**（架构 §26）：用 DeepSeek 完成一个真实的改代码并运行测试的任务，可回退。

## 2. 任务清单

| 编号 | 任务 | 主要内容 | 依赖 | 依据 |
|---|---|---|---|---|
| M1-01 | pi 适配器 | 新建 `packages/runtime-pi`；实现 `AgentRuntime`；`CanonicalMessage` 与 pi 格式双向转换；把 pi 的工具回调接到 `hooks.executeTool`；锁定 pi 精确版本；pi 打进宿主产物（S1），随应用附带打包进来的第三方依赖的许可证声明（`THIRD_PARTY_NOTICES`，ADR-0014）；被中止或出错的一步不发出 `message.completed`，由 `RunEngine` 保存部分回复 | M0-07、S1、S8 | ADR-0004；Runtime §17 |
| M1-02 | 适配器契约测试 | 用录制的模型响应驱动适配器，比对事件序列黄金文件；三种接口格式各至少一组**从真实服务录制**的文件（S8 的录制都是合成的） | M1-01、S8 | 架构 §23；Runtime §18 |
| M1-03 | 凭据服务 | `CredentialProvider`（`local-key`），`safeStorage` 加密存储；`credentials.set/delete/status`；只在 `host.init` 时传给宿主 | M0-13 | ADR-0010；架构 §16.2 |
| M1-04 | 提供方配置与三种接口格式 | `ProviderConfig`（`kind`：`openai` / `anthropic` / `gemini`，可自定义 `baseUrl`）、`ModelProfile`；`provider_configs` 迁移；DeepSeek、Ollama、Anthropic、OpenAI、Gemini 默认配置模板；模板带出模型家族的兼容参数（S2：经代理接入 DeepSeek 时 pi 识别不到，需显式设置 `thinkingFormat` 等），高级设置中可覆盖；各格式推理内容处理 | M1-01、M1-03、S2 | ADR-0011、ADR-0021；架构 §12 |
| M1-05 | 工具注册表与工具流水线 | `ToolDefinition`、`ToolContext`；`ToolPipeline`（校验 → 权限 → 执行 → 输出预算 → 事件） | M0-07 | ADR-0017；架构 §9.1；Runtime §7 |
| M1-06 | 路径校验 | 规范化后限制在工作区内；处理 `..`、符号链接、盘符、大小写、`\\?\`、目录联接 | M0-01 | 架构 §17 |
| M1-07 | 读类工具 | `read_file`、`list_dir`、`search`（随应用打包 ripgrep） | M1-05、M1-06 | 架构 §9.2、§18 |
| M1-08 | 写类工具与改动记录 | `write_file`、`edit_file`；保持换行与 BOM；blob 存储；`file_changes`、`hunks` 迁移 | M1-05、M1-06、M0-09 | ADR-0008；架构 §9.2、§11.1 |
| M1-09 | Shell 适配器与 `run_command` | 新建 `packages/shell`；PowerShell 5.1 / 7 选择、`-EncodedCommand`、UTF-8、超时、进程树结束、环境变量清洗、输出截断 | M1-05、S7 | ADR-0012；架构 §9.3 |
| M1-10 | 权限引擎 | 规则模型、强制拦截（危险命令、敏感文件、工作区外路径）、`deny > ask > allow`、类别默认值、三种预设；`permission_rules` 迁移 | M0-06 | ADR-0007；架构 §10 |
| M1-11 | 审批流程 | `approval.requested/resolved` 事件；`host.approval.*` 消息；界面审批卡片（允许一次 / 本会话 / 本项目 / 拒绝并说明）；重启后未决审批视为取消 | M1-10、M0-15 | 架构 §10.4 |
| M1-12 | 基础检查点 | 新建 `packages/checkpoint`；影子 Git（按 S6 结论选择 Git 来源）；轮次起点与命令前创建；`checkpoint.list/restore`；恢复前自动再建检查点 | S5、S6、M0-09 | ADR-0008；架构 §11 |
| M1-13 | 输出预算与基础上下文 | 按 `ModelProfile.contextWindow` 计算工具输出上限；系统提示词分层（基础 + 用户自定义） | M1-04、M1-05 | 架构 §9.4、§13 |
| M1-14 | 错误处理 | 模型请求退避重试、非法工具调用回传修正、最大步数与单轮时限 | M1-01 | 架构 §21；Runtime §10 |
| M1-15 | 端到端验收 | 在示例项目上用 DeepSeek（手动触发流水线或本地）完成"修改代码 → 运行测试 → 回退"；CI 中用录制回放版本 | 全部 | 架构 §23、§26 |

## 3. 前置条件

- M0 全部完成。
- 预研 S1（pi 在 utilityProcess）、S2（DeepSeek）、S5/S6（检查点）、S7（PowerShell）、S8（契约测试）已有结论。
- 若 S1 失败，M1-01 之前需要先修订 ADR-0003 的进程模型。
