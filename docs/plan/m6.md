## 1. 目标

**完成标准**（架构 §26）：三个平台可用，仓库可以公开。

拆成两件可以分别验收的事：

1. **跨平台**：Windows、macOS、Linux 都能安装、启动、跑通一次真实编码任务，检查点、
   沙箱、凭据与更新在各自平台上都有明确语义，且不把 Windows 假设写进共享接口。
2. **开源**：许可证、贡献指南、行为准则、安全策略、Issue/PR 模板齐全；仓库里没有
   密钥、内部资料与不可分发的二进制；CI 对公开贡献者可用。

### 1.1 不在本轮范围内

- **长期记忆**（ADR-0019）：M5 已确认在 M6 之后单独立项，本轮只保留 `memory` 字段的兼容性。
- **移动端、Web 版、企业分发与 MSIX**：没有真实需求前不评估。
- **遥测与自动回滚**：M6 只做本地日志与诊断包；远端遥测需要单独的隐私方案。
- **重写引擎或更换运行时**：继续使用 pi + `AgentRuntime` 抽象。

## 2. 范围裁决与前提

### 2.1 平台范围

| 平台 | 架构 | 发布形态 | 说明 |
|---|---|---|---|
| Windows | x64 | NSIS 按用户安装 | 延续 M5；M6 只补签名与验收 |
| macOS | arm64 + x64（Universal 或分架构） | DMG + ZIP（更新用） | 首次正式支持；签名与公证依赖开发者账号 |
| Linux | x64 | AppImage + deb | 以 Ubuntu LTS 为基线；其他发行版 best-effort |

- Windows ARM64、Linux arm64、32 位均不在本轮；接口层要为它们留出位置。
- 每个平台至少有一套 CI 冒烟（构建、单测、`smoke`），e2e 在 Windows 与 Linux 上跑；
  macOS 的 e2e 受 runner 限制时，用打包冒烟 + 手工矩阵补齐并记录。

### 2.2 已落定的前提

1. M5 的沙箱、更新、打包实现不把 Windows 假设写进共享接口；M6 只做平台实现与分支。
2. Linux 没有系统密钥环时 `safeStorage` 可能退化为弱加密：**不静默保存**，要么使用
   用户提供的口令派生密钥，要么明确拒绝并给出说明（ADR-0010 的扩展，见 M6-04）。
3. 开源许可证由项目所有者决定；默认候选是 MIT 或 Apache-2.0，决定后新增 ADR。
   已决定：**MIT**，贡献者协议 **DCO**（2026-11-16，见 ADR-0039）。
4. 仓库公开前，历史中的个人路径、内网地址与测试凭据需要清理或确认为样例数据。

### 2.3 需要新增或更新的 ADR

| 主题 | 动作 |
|---|---|
| 开源许可证与贡献者协议 | 新增 ADR（许可证选择、CLA/DCO、商标与名称使用）——已完成 ADR-0039（MIT + DCO） |
| Linux 凭据存储与安全降级 | 扩展 ADR-0010 或新增 ADR |
| macOS 签名与公证 | 新增 ADR（Developer ID、notarytool、更新签名链） |
| 跨平台沙箱语义 | 扩展 ADR-0034（Linux namespace/seccomp、macOS seatbelt 的能力边界） |

## 3. 现状与缺口

### 3.1 已有的跨平台基础

- 路径、shell 选择、Git 定位、工作区校验大多在 `@cairn/core` 与 `@cairn/shell` 中，
  已有少量 Unix 分支与 Linux CI 单测。
- 检查点优先使用本机 Git，Windows 附带 MinGit；macOS/Linux 用户通常已有 Git，
  `ADR-0008` 约定 M6 再评估是否附带。
- `AgentRuntime`、协议与事件模型与平台无关；渲染层没有 Windows 专属 API。
- 打包脚本已区分平台分支，M5 只实现 Windows 目标。

### 3.2 明确的缺口

- macOS：`Menu`、窗口控件、`open`/`say` 等系统命令、路径大小写与符号链接、
  `safeStorage` 后端、签名与公证、DMG 布局、更新源都未适配。
- Linux：`safeStorage` 无密钥环（M6-04 已确定显式拒绝并说明原因）、AppImage 的 `--no-sandbox` 与沙箱冲突、
  `xdg-open`、字体与合成器差异、deb 依赖与桌面项、更新包（AppImage 内更新）。
  （2026-11-16 M6-03 已实现 AppImage/deb 打包、桌面项与校验和，并把 `--no-sandbox` 限定为
  显式排障选项；AppImage 更新元数据与发布 job 已由 M6-07 接入。）
- 沙箱：Windows 受限令牌 / AppContainer 之外的平台实现缺失；M6 先明确
  “默认拒绝 + 显式审批后以用户权限运行”的降级语义，再逐平台实现。
  （2026-11-16 M6-05 已明确：未实现平台不额外拦截，按权限规则（execute 默认询问）在沙箱外
  运行，事件与界面统一标注“未沙箱化”和平台原因，不冒充隔离。）
- 开源材料：`LICENSE` 目前是专有 beta 许可（M5-09），没有 `CONTRIBUTING.md`、
  `CODE_OF_CONDUCT.md`、`SECURITY.md` 与 Issue/PR 模板；README 只有中文。
  （2026-11-16 M6-06 已补齐：MIT、贡献/行为准则/安全文档、Issue/PR 模板与英文 README。）
- 发布流水线：只构建 Windows；签名、公证与更新元数据没有 macOS/Linux 分支。
  （2026-11-16 M6-02 已实现 macOS 打包、Developer ID 签名与公证校验；M6-07 已把 release
  workflow 拆成三平台构建 + 汇总发布，见 ADR-0043。）
- 分支与文档状态：Agent 管理入口在 M4 后被界面重构移除，2026-11-12 已恢复列表、
  编辑器与试运行；会话内 Agent 选择器已于 2026-11-16（M6-08）接回输入框。

### M6-04 凭据存储的跨平台策略与 Linux 降级

- **状态**：已完成（2026-11-16）。决策见 [ADR-0040](../adr/0040-linux-credential-refusal.md)，
  说明见 [凭据存储](../dev/credentials.md)。
- **范围**：检测 `safeStorage` 后端（`basic_text` / 未知视为不可用）；决定口令派生密钥
  （如 Argon2id）或明确拒绝；迁移已有 Windows 凭据的格式说明。
- **交付**：凭据后端适配层、设置页说明与错误文案、单测与文档。
- **验收**：无密钥环的 Linux 上不会静默弱加密；用户能理解为什么需要口令；
  拒绝时不阻塞其它功能。
  - 决定：显式拒绝，不做口令派生密钥（ADR-0040 记录了取舍与后续条件）。
  - 分类：`credentialAvailability()` 把不可用分为 `system-encryption-unavailable`、
    `insecure-linux-backend`、`unknown-linux-backend`，经 `credentials.status` 的 `reason`
    传给界面；设置页按原因给出具体说明（中英文）。
  - 文档：`docs/dev/credentials.md`（文件格式、各平台后端、Linux 密钥环检查与安装、换机器
    与解密失败）；故障排查与架构 §16.2 同步。
  - 测试：分类的每个分支、`LocalKeyStore.unavailableReason` 的有无、命令结果带上/不带
    `reason`、设置页三种原因的文案。

### M6-05 跨平台沙箱语义与降级

- **状态**：已完成（2026-11-16）。语义写入 [ADR-0034](../adr/0034-windows-command-sandbox.md)
  “跨平台语义（M6-05）”。
- **范围**：定义“没有平台沙箱时”的默认策略：拒绝、每次审批后在沙箱外运行、还是只读；
  Linux 评估 namespace/seccomp，macOS 评估 seatbelt；与 ADR-0034 的失败关闭原则一致。
- **交付**：平台沙箱适配层、界面档位显示、诊断包字段、文档。
- **验收**：任何平台都不会声称“已沙箱”却实际未隔离；降级有事件与界面提示。
  - 适配层：`@cairn/shell` 的 `sandboxPlatformSupport()` 集中平台判断；Linux/macOS 给出各自的
    `sandbox.platform_unsupported_*` 原因，其他平台用通用原因；探测不再进入 Win32 API。
  - 默认策略：没有沙箱的平台保持权限模型（`execute` 类默认询问，用户显式放行后在沙箱外运行），
    不额外拦截；`SandboxExecution.enforced=false` 且带平台原因，`tool.started`、终端、审批卡片

### M6-07 跨平台 CI 与发布流水线

- **状态**：已完成（2026-11-16；真实标签发布与外部账号验收见“未验证”）。决策见
  [ADR-0043](../adr/0043-cross-platform-ci-and-release.md)。

  - CI：`check` 矩阵加入 `macos-latest`；三平台都执行 `package:dir`、`package:verify` 与
    `smoke:packaged`，Playwright e2e 保持 Windows + Linux，macOS 用打包冒烟覆盖；
    新增 `dco` job 对 PR 的非合并提交校验 `Signed-off-by`。
  - 发布结构：`prepare` → `build-windows` / `build-macos` / `build-linux` → `assemble` →
    `publish`。每个构建 job 上传 `cairn-release-<version>-<platform>`，`assemble` 用
    `release:merge` 合并发布说明、provenance 与 `SHA256SUMS`，`publish` 只上传一次。
  - 更新元数据：Windows `latest.yml`/`beta.yml`、macOS `latest-mac.yml`/`beta-mac.yml`、
    Linux `latest-linux.yml`/`beta-linux.yml`；`release:artifacts --platform` 校验
    electron-builder 元数据与每个可更新产物逐项一致。
  - 签名降级：Windows/macOS 的 beta 构建失败时用 unsigned 重试一次并在发布说明标注；
    stable 要求 Windows 签名或 macOS `developer-id`，Linux stable 允许 unsigned。
  - macOS 双架构：同一 job 保留 `darwin-arm64.node` 与 `darwin-x64.node`，并固定
    `mac.artifactName`，避免 x64 应用加载 arm64 原生模块或 ZIP 命名漂移。

    解析与提交范围；`packaging.test.ts`、`smoke-packaged.test.ts`、`packaged-app.test.ts`
    覆盖 macOS 预编译保留、非 Windows 不校验 MinGit 与按架构定位应用。
  - 文档：ADR-0043、`docs/dev/release.md` §12、本计划与架构 §24。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| macOS 签名/公证账号未就绪 | 无法产出可分发 DMG | 先出 unsigned 内部包；签名作为 M6-02 的收尾门槛，不阻塞其它平台 |
