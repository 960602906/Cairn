# Cairn 里程碑 6：跨平台与开源

> 状态：规划中（2026-11-12 起草）。M0～M5 已实施，0.1.0 unsigned beta 可安装分发；
> M5 的 stable 阻塞项（签名、法务、干净 VM 矩阵）在 M6 里继续收口。
> 上级文档：[架构设计](../architecture.md) 第 26 节；前一阶段：[M5](m5.md)、[M5 验收报告](m5-report.md)。
> 相关设计：[视觉规范](../design/visual-style.md)、[Agent 管理界面](../design/agent-management-ui.md)、
> [发布运行手册](../dev/release.md)、[发布前置条件](m5-release-prerequisites.md)。
> 相关决策：ADR-0002、ADR-0008、ADR-0010、ADR-0014、ADR-0034～0036。

## 1. 目标

**完成标准**（架构 §26）：三个平台可用，仓库可以公开。

拆成两件可以分别验收的事：

1. **跨平台**：Windows、macOS、Linux 都能安装、启动、跑通一次真实编码任务，检查点、
   沙箱、凭据与更新在各自平台上都有明确语义，且不把 Windows 假设写进共享接口。
2. **开源**：许可证、贡献指南、行为准则、安全策略、Issue/PR 模板齐全；仓库里没有
   密钥、内部资料与不可分发的二进制；CI 对公开贡献者可用。

### 1.1 不在本轮范围内

- **长期记忆**（ADR-0019）：M5 已确认在 M6 之后单独立项，本轮只保留 `memory` 字段的兼容性。
- **移动端、Web 版、企业分发与 MSIX**：没有真实需求前不评估。
- **遥测与自动回滚**：M6 只做本地日志与诊断包；远端遥测需要单独的隐私方案。
- **重写引擎或更换运行时**：继续使用 pi + `AgentRuntime` 抽象。

## 2. 范围裁决与前提

### 2.1 平台范围

| 平台 | 架构 | 发布形态 | 说明 |
|---|---|---|---|
| Windows | x64 | NSIS 按用户安装 | 延续 M5；M6 只补签名与验收 |
| macOS | arm64 + x64（Universal 或分架构） | DMG + ZIP（更新用） | 首次正式支持；签名与公证依赖开发者账号 |
| Linux | x64 | AppImage + deb | 以 Ubuntu LTS 为基线；其他发行版 best-effort |

- Windows ARM64、Linux arm64、32 位均不在本轮；接口层要为它们留出位置。
- 每个平台至少有一套 CI 冒烟（构建、单测、`smoke`），e2e 在 Windows 与 Linux 上跑；
  macOS 的 e2e 受 runner 限制时，用打包冒烟 + 手工矩阵补齐并记录。

### 2.2 已落定的前提

1. M5 的沙箱、更新、打包实现不把 Windows 假设写进共享接口；M6 只做平台实现与分支。
2. Linux 没有系统密钥环时 `safeStorage` 可能退化为弱加密：**不静默保存**，要么使用
   用户提供的口令派生密钥，要么明确拒绝并给出说明（ADR-0010 的扩展，见 M6-04）。
3. 开源许可证由项目所有者决定；默认候选是 MIT 或 Apache-2.0，决定后新增 ADR。
4. 仓库公开前，历史中的个人路径、内网地址与测试凭据需要清理或确认为样例数据。

### 2.3 需要新增或更新的 ADR

| 主题 | 动作 |
|---|---|
| 开源许可证与贡献者协议 | 新增 ADR（许可证选择、CLA/DCO、商标与名称使用） |
| Linux 凭据存储与安全降级 | 扩展 ADR-0010 或新增 ADR |
| macOS 签名与公证 | 新增 ADR（Developer ID、notarytool、更新签名链） |
| 跨平台沙箱语义 | 扩展 ADR-0034（Linux namespace/seccomp、macOS seatbelt 的能力边界） |

## 3. 现状与缺口

### 3.1 已有的跨平台基础

- 路径、shell 选择、Git 定位、工作区校验大多在 `@cairn/core` 与 `@cairn/shell` 中，
  已有少量 Unix 分支与 Linux CI 单测。
- 检查点优先使用本机 Git，Windows 附带 MinGit；macOS/Linux 用户通常已有 Git，
  `ADR-0008` 约定 M6 再评估是否附带。
- `AgentRuntime`、协议与事件模型与平台无关；渲染层没有 Windows 专属 API。
- 打包脚本已区分平台分支，M5 只实现 Windows 目标。

### 3.2 明确的缺口

- macOS：`Menu`、窗口控件、`open`/`say` 等系统命令、路径大小写与符号链接、
  `safeStorage` 后端、签名与公证、DMG 布局、更新源都未适配。
- Linux：`safeStorage` 无密钥环、AppImage 的 `--no-sandbox` 与沙箱冲突、
  `xdg-open`、字体与合成器差异、deb 依赖与桌面项、更新包（AppImage 内更新）。
- 沙箱：Windows 受限令牌 / AppContainer 之外的平台实现缺失；M6 先明确
  “默认拒绝 + 显式审批后以用户权限运行”的降级语义，再逐平台实现。
- 开源材料：`LICENSE` 目前是专有 beta 许可（M5-09），没有 `CONTRIBUTING.md`、
  `CODE_OF_CONDUCT.md`、`SECURITY.md` 与 Issue/PR 模板；README 只有中文。
- 发布流水线：只构建 Windows；签名、公证与更新元数据没有 macOS/Linux 分支。
- 分支与文档状态：Agent 管理入口在 M4 后被界面重构移除，2026-11-12 已恢复列表、
  编辑器与试运行；会话内 Agent 选择器尚未接回输入框。

## 5. 任务详情

### M6-00 预研与文档基线

- **范围**：确认平台矩阵与最低系统版本；列出共享代码里的 Windows 假设；
  比较许可证候选（MIT / Apache-2.0）与贡献者协议；输出仓库公开检查清单。
- **交付**：`docs/plan/m6-spikes.md`、更新本文与架构 §26；许可证决定写成 ADR。
- **验收**：每条平台结论都有可复现的命令或文档引用；许可证与贡献流程获所有者确认。

### M6-01 平台抽象审计与共享接口收口

- **范围**：审计 `platform`、`shell`、`paths`、`git`、`safeStorage`、`sandbox`、更新与打包脚本；
  把散落的 `process.platform` 判断收进少量具名适配层，补上“不支持”时的明确错误。
- **交付**：适配层与类型；单测覆盖每个平台分支（用注入的平台标识，不靠真实平台）。
- **验收**：共享包里不再出现未封装的平台判断；新增平台只实现接口，不改调用方。

### M6-02 macOS 适配、签名、公证与打包

- **范围**：窗口控件与菜单（红绿灯、`Cmd` 快捷键）、`Cmd` 与 `Ctrl` 映射、系统命令、
  DMG 布局、Developer ID 签名与 `notarytool` 公证、ZIP 更新包与 `latest-mac.yml`。
- **交付**：`package:mac`、签名/公证脚本、DMG 安装说明、更新源分支。
- **验收**：Apple Silicon 与 Intel 各一台（或 CI runner）安装、启动、跑通一次任务；
  公证通过；更新检查/下载/校验可用。

### M6-03 Linux 适配与打包

- **范围**：AppImage 与 deb、桌面项与图标、`xdg-open`、字体与合成器差异、
  无密钥环时的凭据策略（配合 M6-04）、AppImage 内更新、`--no-sandbox` 与命令沙箱的关系。
- **交付**：`package:linux`、安装与故障排查文档、Ubuntu LTS 验收记录。
- **验收**：Ubuntu LTS 上安装、启动、跑通一次任务；卸载/重装保留设置；
  更新包可下载、校验并安装。

### M6-04 凭据存储的跨平台策略与 Linux 降级

- **范围**：检测 `safeStorage` 后端（`basic_text` / 未知视为不可用）；决定口令派生密钥
  （如 Argon2id）或明确拒绝；迁移已有 Windows 凭据的格式说明。
- **交付**：凭据后端适配层、设置页说明与错误文案、单测与文档。
- **验收**：无密钥环的 Linux 上不会静默弱加密；用户能理解为什么需要口令；
  拒绝时不阻塞其它功能。

### M6-05 跨平台沙箱语义与降级

- **范围**：定义“没有平台沙箱时”的默认策略：拒绝、每次审批后在沙箱外运行、还是只读；
  Linux 评估 namespace/seccomp，macOS 评估 seatbelt；与 ADR-0034 的失败关闭原则一致。
- **交付**：平台沙箱适配层、界面档位显示、诊断包字段、文档。
- **验收**：任何平台都不会声称“已沙箱”却实际未隔离；降级有事件与界面提示。

### M6-06 开源材料与仓库公开

- **范围**：替换专有 beta 许可；补 `CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、
  `SECURITY.md`、Issue/PR 模板、英文 README；清理历史中的敏感信息与内部资料；
  确认第三方许可证与源码获取方式（MinGit、ripgrep、Electron 等）。
- **交付**：上述文件、公开前检查清单的执行记录、ADR（许可证与贡献者协议）。
- **验收**：公开仓库可被外部贡献者构建、测试与提交 PR；`check:licenses` 通过；
  没有密钥或内部地址。

### M6-07 跨平台 CI 与发布流水线

- **范围**：CI 矩阵（Windows / Ubuntu / macOS）：format、typecheck、lint、i18n、
  licenses、单测与覆盖率、e2e（至少 Windows + Linux）；发布 workflow 按平台构建、
  签名/公证、生成更新元数据与校验和。
- **交付**：workflow、缓存与超时策略、失败重试说明。
- **验收**：三个平台的流水线可重复执行；标签构建能产出可下载产物；
  签名失败时降级为 unsigned 并在发布说明标注。

### M6-08 桌面体验收尾

- **范围**：把会话内 Agent 选择器接回输入框（`AgentPicker`，只列已发布 Agent，
  最近使用优先，运行中不可切换）；检查侧栏入口与设置页的信息架构是否一致；
  补界面截图（浅色/深色）与空状态。
- **交付**：组件、store 接线、单测/e2e、截图。
- **验收**：会话里可以切换 Agent 且只出现可用版本；入口、返回路径与快捷键一致。

### M6-09 稳定版阻塞项收口

- **范围**：Windows 代码签名（OV/EV 云签名）、法务确认 EULA/隐私文本、干净 VM 与
  标准用户矩阵、真实 `0.1.0 → 0.1.1` 更新演练。
- **交付**：签名产物、验收记录、更新演练日志。
- **验收**：`signtool verify` 通过；干净 VM 完成安装→使用→更新→卸载→重装；
  发布说明与报告更新。

### M6-10 全流程验收、文档与收尾

- **范围**：三平台全流程 e2e/手工矩阵；覆盖率与质量门槛；架构、ADR、README、
  CHANGELOG 与本文实施记录同步；清理已合并或替代的远程分支
  （`codex/ui-followups-20261109` 已与 `main` 等价；`codex/ui-p0-p1-fixes`、
  `codex/composer-slash-commands` 的实现已被后续 PR 取代）。
- **交付**：验收报告 `docs/plan/m6-report.md`、分支清理记录。
- **验收**：架构 §26 的 M6 完成标准逐项打勾；没有未记录的已知问题。

## 6. 验收与测试矩阵

| 门槛 | Windows | macOS | Linux |
|---|---|---|---|
| format / typecheck / lint / i18n / licenses | CI | CI | CI |
| 单测 + 四项覆盖率 ≥ 95% | CI | CI | CI |
| `build` / `smoke`（fake 与 pi） | CI | CI | CI |
| e2e（核心会话流程） | CI | 手工/打包冒烟 | CI |
| 安装包构建与安装 | NSIS | DMG | AppImage / deb |
| 更新检查/下载/校验 | 自动化 | 待签名产物 | 自动化 |
| 命令沙箱 | 受限令牌/AppContainer | seatbelt 评估 | namespace/seccomp 评估 |
| 检查点（本机 Git / 随包 Git） | 本机 + MinGit | 本机 Git | 本机 Git |

每个任务的证据要求：单测、集成、组件、e2e 中至少两类；界面改动附浅色/深色截图。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| macOS 签名/公证账号未就绪 | 无法产出可分发 DMG | 先出 unsigned 内部包；签名作为 M6-02 的收尾门槛，不阻塞其它平台 |
| Linux 无密钥环导致凭据不可用 | 用户无法保存 API Key | M6-04 先给出口令派生密钥或明确拒绝，不静默弱加密 |
| 沙箱语义在非 Windows 平台难以对齐 | 安全承诺失真 | 显式降级 + 界面标注 + ADR 更新；不为“看起来可用”而假称已隔离 |
| 公开仓库前遗漏敏感信息 | 安全事故 | M6-00 检查清单 + 历史扫描（密钥、路径、内部地址）；必要时重写历史 |
| 跨平台 CI 成本与时长 | 提交反馈变慢 | 只在 PR 跑受影响平台的必需门槛；夜间跑完整矩阵 |
| 范围蔓延（记忆、移动端、企业分发） | M6 无法收尾 | §1.1 明确排除；新需求进入 M6 之后单独立项 |
