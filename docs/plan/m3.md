## 1. 目标

**完成标准**（架构 §26）：可以长期在真实项目中使用，可自定义 Agent 并接入外部工具。

具体来说：

1. 长对话不会撑爆上下文：接近上限时自动压缩，压缩后仍能继续工作；会话要点保住用户说过的目标和约束。
2. 项目说明（`AGENTS.md`）、全局说明、Skills 进入上下文，用户能看到实际加载了什么。
3. 可以接入 MCP 服务（本地进程与远程地址），MCP 工具与内置工具一样经过权限判定和审批。
4. 大改动可以先规划再动手（计划模式）；改动可以按块撤销。
5. 可以创建自己的 Agent（指令、模型、工具、Skills、权限、限额），在会话中选择使用。
6. 出问题时能导出脱敏的诊断包。

### 1.1 不在本轮范围内

- 多 Agent 委派、子运行、运行树：M4（多 Agent 协作设计）。
- 活动中心、跨会话的待审批列表、系统通知、检查器（运行时间线 / 上下文快照）：M4，与多会话并行一起做。侧栏“活动”入口在 M4 之前仍不显示。
- Agent 试运行面板：M4（试运行依赖检查器与活动中心的大部分组件）。M3 的 Agent 先发布、再在普通会话中验证；草稿不能在会话中使用。
- 记忆（ADR-0019）：只预留，编辑器中“记忆”分区显示“即将推出”。
- 后台命令、git worktree 隔离：M4。
- 安装包与签名：M5。
- 任何金额、价格、预算显示：不做（视觉规范 §10）。限额中不提供“费用上限”。
- 登录与账户：没有。模型供应商只支持 Anthropic / OpenAI / Gemini 三种接口格式（ADR-0021）。

### 1.2 任务约定

沿用 M0 ～ M2 的约定：

- 一个子任务一个 PR，标题形如 `feat(core): 上下文压缩 [M3-03]`，合并后再开始下一个。PR 描述、提交信息、文档用中文。
- 每个 PR 同时更新本文：§3 的“状态”一行，以及对应任务下的“实施记录”（做了什么、与计划的差异及原因）。
- 提交前在仓库根目录运行：`pnpm format`、`pnpm typecheck`、`pnpm lint`、`node scripts/check-i18n.js`、`pnpm test:coverage`（四项覆盖率不低于 90%）。改到桌面端时再运行 `apps/desktop` 下的 `pnpm build` 与 e2e（Linux 容器中用 `xvfb-run -a pnpm e2e -- --trace off`）。
- 界面文案全部走 i18n（ADR-0013），`packages/i18n/locales/zh-CN` 与 `en-US` 同时补齐；lint 规则 `cairn/no-literal-ui-text` 不允许在组件里写死文字。
- 组件只用设计令牌（`styles/tokens.css`）的颜色；界面 PR 附浅色、深色截图。
- 新依赖取最新稳定版，通过许可证检查（ADR-0014，`scripts/license-exceptions.json`）；工作区内新包要同时加入 `apps/desktop` 的依赖和 `electron.vite.config.ts` 的 `workspacePackages`，否则宿主打包会失败。
- 新的协议类型、事件、RPC 写在 `packages/protocol`（zod），主进程实现在 `apps/desktop/src/main/services/`，经 `renderer-gateway.ts` 暴露给渲染进程；`packages/core` 不引用 DOM、Node、Electron 类型。
- API Key、MCP 令牌等凭据只经过凭据服务（ADR-0010，`safeStorage`），不写进配置、日志、事件、诊断包、PR 描述。
- 涉及新的架构决定时补 ADR（编号从 0026 起），在任务的“实施记录”里引用。

## 2. 技术选型

| 用途 | 选择 | 说明 |
|---|---|---|
| MCP 客户端 | `@modelcontextprotocol/sdk`（官方 TypeScript SDK，MIT） | 支持 stdio 与 Streamable HTTP（旧的 SSE 传输作为回退）。写 ADR-0026：MCP 连接放在主进程，宿主经 RPC 调用 |

| 诊断包 | `fflate`（MIT）生成 zip | 纯 JS，无原生依赖 |
| 指令编辑器 | 先用自动增高的 `textarea` + 等宽字体 + token 估算 | Monaco 体积大，等确实需要再引入 |
| 辅助模型调用 | `packages/runtime-pi` 增加一次性的“无工具补全”接口 | 标题、会话要点、压缩摘要都走它 |

## 4. 任务详情

### M3-01 辅助模型与自动标题

- **目的**：生成标题、会话要点、压缩摘要这类“小活”交给便宜快速的模型，主模型专心干活（Runtime §25.2，管理界面 §4.2“辅助模型”）。
- **交付物**
  - 设置新增 `auxiliaryModel?: ModelRef`（`Settings` 与 `SettingsPatch`，校验规则与 `defaultModel` 相同：必须是已配置的模型，删除供应商或模型时一并清除）。没有配置时使用会话当前的主模型。
  - `packages/runtime-pi` 增加 `complete({ model, systemPrompt, messages, maxOutputTokens, signal })`：一次不带工具的补全，返回文本与用量。思考型模型的推理内容丢弃；失败时按现有重试规则（Runtime §10.4）。
  - 自动标题：会话第一轮结束后，如果标题仍为空，用辅助模型根据第一条用户消息和回复生成不超过 30 个字符的标题（语言跟随用户），记为 `session.renamed`。用户手动改过标题的会话不再自动改。失败只写日志，不提示用户。
  - 辅助模型的用量记为 `usage.reported`（带模型），计入会话 token 统计，但不计入上下文圆环。
  - 设置页“模型供应商”顶部加“辅助模型”下拉（含“与主模型相同”）。
- **验收**：单测覆盖设置校验、标题生成的触发条件（只在首轮、标题为空、未手动改过）；用本地 mock 模型的 e2e 验证新会话自动得到标题。

### M3-02 项目说明 `AGENTS.md` 与项目设置页

- **交付物**
  - 系统提示词第 3 层（`packages/core/src/system-prompt.ts` 注释中已预留）：每轮开始时读取项目根目录的 `AGENTS.md`（大小写不敏感；超过 32 KB 截断并注明），用 `# Project instructions (AGENTS.md)` 标题包住。内容是不可信的项目文件，仍放在安全规则之后。
  - 每轮记录实际读到的版本：`turn.started` 增加可选字段 `context: { agentsMd?: { sha256, bytes, truncated } }`，便于追溯。
  - 设置页新增“项目”分区（`general` 组）：列出已打开的项目（名称、路径、会话数、最近使用），可以重命名、从列表移除（只移除记录，不删文件，确认框说明这一点）；每个项目的开关：读取 `AGENTS.md`（默认开）、启用项目内 Skills（默认关，M3-07 起生效）。
  - 顶栏会话标题旁，当本轮读取了 `AGENTS.md` 时显示一个小标记，悬停显示“已加载项目说明 AGENTS.md（N 行）”。
- **后端**：`project.update`（名称、开关）、`project.remove`；项目设置存进 `projects` 表（新迁移 0006）。
- **验收**：快照测试覆盖有 / 无 / 过大的 `AGENTS.md`；关闭开关后不再读取；e2e：项目里放一个 `AGENTS.md`，模型请求的系统提示词中包含它。

### M3-03 上下文压缩

- **设计依据**：Runtime §8.3。写 ADR-0027 记录方案。
- **交付物**
  - 触发：每次调用模型之前（`RuntimeHooks.beforeModelCall`，接口已有但 `runtime-pi` 还没接上，需要接到 pi 的上下文变换钩子上）估算占用；历史超过“上下文窗口 − 预留输出 − 系统提示词与工具定义”的 80% 时压缩。
  - 做法：保留最近 2 轮完整内容；更早的部分用辅助模型总结，摘要保留用户目标、已做的决定、改过的文件、未完成事项（有会话要点时一并带上，M3-04 之后）。摘要作为一条带标记的用户消息放在历史开头。
  - 事件：`context.compacted`（已有）补全字段：被替换的 seq 范围、摘要文本、压缩前后的估算 token。恢复会话时 `rebuildHistory` 按最后一次压缩重建历史，而不是重新发送全部原始消息。
  - 失败退化：摘要失败时丢弃最早的工具输出内容（保留调用记录与“输出已省略”说明），并在对话中提示一次。
  - 手动压缩：输入框发送 `/compact` 时立即压缩（不是发给模型的消息）。
  - 界面：对话中在被压缩的位置显示分隔线“较早的对话已压缩”，可以展开查看摘要；原始消息仍然显示，不删除。上下文圆环在压缩后下降。
- **验收**：core 单测（触发阈值、保留轮数、工具调用配对不被拆开、失败退化、恢复后的历史）；用 mock 模型构造小上下文窗口（如 4 000）的 e2e，连续多轮后发生压缩，会话仍能继续。

### M3-04 会话要点

- **设计依据**：Runtime §25.2。
- **交付物**
  - 每轮结束后由辅助模型增量更新，只收录用户明确提出的目标、约束和偏好，不收录模型的推断；记为 `session.brief.updated`（事件已定义）。与上一版相同时不发事件。
  - 对话页顶栏“更多”菜单中加“会话要点”，打开右侧抽屉：显示要点（Markdown），可以编辑；用户编辑后的版本优先，之后的自动更新只在其基础上追加。
  - 压缩时要点作为必须保留的内容放进摘要之前（M3-03）。
  - 设置“通用”中可以关闭自动更新会话要点（默认开）。
- **验收**：单测覆盖“无变化不发事件”“用户编辑优先”；e2e 用 mock 模型验证要点抽屉显示与编辑。

### M3-05 计划模式

- **设计依据**：Runtime §25.1。写 ADR-0028 记录计划的结构与工具。
- **交付物**
  - 协议：`session.prompt` 增加 `mode: 'normal' | 'plan'`；事件 `plan.proposed`、`plan.approved`、`plan.rejected`、`plan.step.updated` 已定义，`plan.proposed` 的 `content` 改为结构化计划：`{ goal, files[], steps[{ id, title }], risks, verification }`（保留 Markdown 原文以便显示）。
  - 计划模式中本轮有效权限临时收紧为只读（写、执行、网络一律拒绝，拒绝原因说明“计划模式下只能阅读”），并多提供一个工具 `propose_plan`（参数即上面的结构）；系统提示词追加计划模式说明。模型调用 `propose_plan` 后本轮结束。
  - 计划卡片：目标、涉及的文件、步骤、风险、验证方式；按钮：批准执行、修改后批准（就地编辑步骤文字）、重新规划（附说明）、放弃。批准后以正常模式开始新的一轮，输入为批准的计划；执行时模型用工具 `update_plan_step`（`{ stepId, status: 'in_progress' | 'done' | 'skipped', note? }`）更新进度，卡片上显示进度。偏离计划不阻止，只在卡片中标注模型的说明。
  - 输入框：权限模式旁加“计划”开关（快捷键 Shift+Tab 在“正常 / 计划”间切换）。
- **验收**：core 单测（只读收紧、`propose_plan` 结束本轮、步骤更新）；e2e：mock 模型提出计划 → 批准 → 按步骤执行并更新进度。

### M3-06 按块撤销

- **现状**：迁移 0004 已建 `hunks` 表并为每条改动记录了块（M1），界面只做了整文件撤销（M2-07）。
- **交付物**
  - 后端：`changes.revertHunk({ changeId, hunkIndex })`：只撤销这一块。前提是文件当前内容中这一块的“改后”内容仍在原位附近（按上下文行定位，允许整体偏移）；对不上时返回错误 `changes.hunk_conflict`，提示用户改用整文件撤销。撤销后更新块状态为 `reverted`，并记一条 `file.changed`（`revert_of` 指向原改动），与整文件撤销一样可以被检查点恢复。
  - 改动的所有块都撤销后，改动状态变为 `reverted`；部分撤销时显示“已撤销 1/3 块”。
  - diff 卡片：每个块的头部（`@@` 行）右侧悬停出现“撤销此块”；已撤销的块变灰并标注。
- **验收**：单测覆盖偏移定位、冲突、全部撤销后状态、检查点恢复后状态；e2e：一次改动两处，撤销其中一块，文件内容只恢复那一块。

### M3-07 Skills 后端

- **设计依据**：Runtime §21.2，ADR-0017。
- **交付物**
  - 新包 `packages/skills`：扫描目录、解析 `SKILL.md`（YAML 头部 `name`、`description` 必填，其余字段保留），计算内容哈希，列出附带文件，标记是否含脚本。
  - 来源：内置（随应用，先放一个示例 Skill 验证流程即可）、用户安装（应用数据目录 `skills/`）、项目内（`.agents/skills/` 或 `.cairn/skills/`，项目设置中开启后才生效，M3-02）。
  - 上下文：系统提示词加 Skills 索引（每个启用的 Skill 一行：名称 + 描述），在环境信息之前；`pinned` 的 Skill 每轮完整注入。
  - 工具 `load_skill({ name })`：返回 `SKILL.md` 正文与附带文件列表，类别为读取，默认允许；附带的参考资料通过 `read_file` 读取（路径允许 Skill 目录，只读）；脚本只能经 `run_command` 执行，照常审批。
  - 记录：`tool.completed` 中记下加载的 Skill 名称与哈希，便于追溯。
  - RPC：`skill.list`、`skill.get`、`skill.install`（从本地文件夹或 zip 安装，先返回预览：`SKILL.md`、文件列表、是否含脚本，再确认安装）、`skill.uninstall`、`skill.setEnabled`。
- **验收**：解析与安装的单测（缺字段、重名、zip 中的路径穿越）；e2e：安装一个 Skill，mock 模型调用 `load_skill` 后拿到正文。

### M3-08 设置页“技能”

- **交付物**（参考稿设置页“技能”分区，管理界面 §10.1）：新分组“能力”，分区“技能”：列表（名称、描述、来源：内置 / 已安装 / 项目、启用开关、“始终加载”开关、token 数）；“安装技能”（选择文件夹或 zip → 预览 → 安装，含脚本时提示“脚本执行时仍需审批”）；详情（`SKILL.md` 渲染预览、文件列表）；卸载（确认框）。项目 Skill 标注所属项目。
- **验收**：组件测试；截图；e2e 覆盖安装与卸载。

### M3-09 MCP 后端

- **设计依据**：Runtime §21.3，ADR-0017；本任务写 ADR-0026。
- **交付物**
  - 新包 `packages/mcp`：基于官方 SDK 的连接管理器（启动、连接、超时、断线重连带退避、退出时结束子进程树），stdio 与 Streamable HTTP 两种传输。
  - 主进程 `mcp-service`：保存服务配置（新迁移：名称、类型、命令 / 参数 / 工作目录 / 环境变量名、或地址与认证方式、启用状态）；环境变量值与令牌存进凭据服务，配置里只存引用；应用启动时连接已启用的服务；状态变化通过事件推给渲染进程；保留每个服务最近 200 行连接日志（脱敏）。
  - 工具适配：每个 MCP 工具变成 `ToolDefinition`，名称为 `服务名.工具名`（只保留 `[a-z0-9_-]`，过长截断并保证唯一）；`ToolDefinition` 增加 `source` 与 `trust`（Runtime §21.3）。默认权限 `ask`；用户可以按工具设置类别（读取 / 写入 / 执行 / 网络）与默认效果，未设置时类别按 `network` 处理。
  - 执行路径：宿主不直接连 MCP。宿主在 `host.init` 中拿到可用的 MCP 工具定义，调用时经新的 host→main 请求 `host.mcp.call` 由主进程执行，结果按工具输出预算截断后返回；取消信号一路传到 SDK。
  - 服务断开时其工具从下一轮起不再提供给模型；进行中的调用返回错误。
  - RPC：`mcp.list`、`mcp.add`、`mcp.update`、`mcp.remove`、`mcp.reconnect`、`mcp.tools`、`mcp.logs`，事件 `mcp.status`。
- **验收**：用测试用的 stdio MCP 服务（仓库内的小脚本）做集成测试：连接、列出工具、调用、超时、崩溃后重连、凭据不出现在日志；e2e：添加服务，mock 模型调用其工具，审批后得到结果。

### M3-10 设置页“MCP 服务”

- **交付物**（参考稿设置页“MCP”分区，管理界面 §10.2）：“能力”分组下的“MCP 服务”分区：列表（名称、类型、连接状态、工具数、启用开关）；添加 / 编辑表单（本地进程：命令、参数、环境变量，敏感值显示“已设置”；远程：地址、认证方式与令牌），保存后立即连接并显示结果与工具列表；详情：工具列表（每个工具的类别与默认效果）、连接日志、重新连接、停用、删除。
- **验收**：组件测试；截图；e2e 覆盖添加、连接失败的提示、删除。

### M3-11 自定义 Agent 后端

- **设计依据**：Runtime §3（Agent 定义）、ADR-0016，管理界面 §5、§11、§16。
- **交付物**
  - 协议：完整的 `AgentDefinition`（Runtime §3.1；`limits` 不含费用上限，`memory` 只预留）、校验结果类型。
  - 存储（新迁移）：`agents`（id、来源、归档、草稿 JSON）与 `agent_versions`（id、版本、定义 JSON、发布时间）。内置 Agent `builtin.coder` 由代码提供，只读，版本随应用。
  - 运行：创建运行时按 `id@version` 取定义：指令进入系统提示词第 2 层；工具与 MCP 工具按 `ToolSelection` 过滤；Skills 按 `SkillSelection`；权限预设与规则叠加（仍是“最严格的胜出”）；限额（步数、时长、token、连续工具错误）；模型为“固定”时忽略会话模型。
  - 会话中切换 Agent：在同一会话中新建运行，之前的对话作为历史传入，记 `run.created`（新 Agent 引用）；运行中不能切换。
  - RPC：`agent.list`、`agent.get`、`agent.saveDraft`（返回校验结果）、`agent.publish`、`agent.duplicate`、`agent.archive` / `agent.unarchive` / `agent.delete`（只限从未被运行引用过的）、`agent.versions`、`agent.diff`、`agent.export` / `agent.import`（Markdown + YAML 头部，导入后为草稿）、`agent.effectiveConfig`（合并后的系统提示词、最终工具清单、Skills 索引、生效的权限规则、上下文预算分配）、`session.setAgent`。
- **验收**：单测覆盖校验、版本递增、发布后草稿与已发布互不影响、删除限制、导入导出往返、生效配置；集成测试：自定义 Agent 只开 `read_file` 时模型看不到其他工具。

### M3-12 Agents 页面与 Agent 选择器

- **交付物**（管理界面 §3 ～ §5、§7，按 ADR-0024 的对话风样式）
  - 侧栏显示“Agents”入口（“活动”仍隐藏）。Agents 页：列表（图标、名称、描述、来源、版本、状态：已发布 / 有未发布修改 / 已归档，筛选与搜索）；空状态“基于编程助手创建你的第一个 Agent”。
  - 编辑器：左侧分区导航（基本信息、指令、模型、能力、权限、限额、上下文、记忆“即将推出”），右侧表单；顶部操作栏（保存草稿 Ctrl+S、发布、复制、导出、归档）；分区上显示未保存 / 警告 / 错误标记；离开时有未保存修改则提示。指令编辑区显示估算 token 与占上下文的比例。
  - 版本历史与对比（结构化字段表格对比，指令文本 diff，可“恢复为草稿”）；发布确认框列出变化摘要和警告。

- **验收**：组件测试；浅色 / 深色截图；e2e：复制编程助手 → 改指令 → 发布 → 在会话中选用，模型请求的系统提示词包含新指令。

### M3-13 诊断包

- **设计依据**：架构 §20、§21。
- **交付物**
